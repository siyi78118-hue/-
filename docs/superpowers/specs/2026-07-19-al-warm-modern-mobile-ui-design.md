# AL 温润现代手机端 UI 设计

日期：2026-07-19  
状态：待用户书面复核  
目标版本：1.0.73

## 1. 目标

在不改变现有聊天、虞栖桥接、主动消息、人物导入、安排表、记忆、诊断和设置逻辑的前提下，将整个 AL 手机端统一升级为“温润现代”视觉风格。

界面应像一款长期使用的真实通讯软件：亲密、克制、耐看，有生活感，但不呈现为 AI 控制台。用户日常接触到的是人物、关系和消息；模型、记忆、同步及恢复能力继续在后台运行。

## 2. 已确认的设计方向

采用视觉方案 A：温润现代。

- 暖白和浅米灰作为主要背景。
- 玉绿色作为品牌色和主要操作色。
- 使用柔和圆角、轻量分隔线和低对比阴影建立层次。
- 保留用户熟悉的微信式导航和交互位置，降低重新学习成本。
- 加入 AL 自己的色彩、圆角和排版节奏，不做逐像素微信复制。

## 3. 明确边界

### 3.1 本次包含

- 全局色彩、字号、间距、圆角、阴影和触摸反馈。
- 顶栏、底部导航、搜索、列表、头像、徽标和空状态。
- 聊天页、消息气泡、输入栏、失败提示和操作面板。
- 通讯录、人物资料、聊天详情和个人资料。
- 发现、朋友圈、钱包和支付相关页面。
- 设置、人物导入、安排表、阶段设定、记忆管理和诊断页面。
- 弹窗、底部抽屉、Toast、加载、禁用、错误和危险操作状态。
- Android 安全区、小屏幕、键盘弹出和较大字体下的适配。

### 3.2 本次不包含

- 不修改虞栖的人物设定、回复逻辑或预设。
- 不修改数据库结构、桥接协议、Cloudflare 服务或小 g 窗口分工。
- 不新增社交功能，不删除现有功能。
- 不把记忆备份、模型、小 g、同步状态虚构成联系人或聊天消息。
- 不使用大量动画、玻璃特效或高饱和渐变制造“AI 产品感”。

## 4. 用户可见信息原则

日常界面只呈现人与关系。

- 消息列表只显示真实会话和已有的用户可见系统会话。
- 主动消息与普通回复沿用同一人物会话，不另建“任务”“记忆”或“模型”会话。
- 记忆、模型、桥接和恢复入口统一留在现有维护页面或“高级设置”层级。
- 正常运行时不展示技术状态。
- 故障确实需要用户处理时，使用一句可理解的结果提示，并提供“查看原因”入口；不直接倾倒日志、内部指令或模型术语。

## 5. 视觉系统

### 5.1 核心颜色

| 用途 | 色值 |
| --- | --- |
| 应用背景 | `#F3F0EA` |
| 顶栏与主要表面 | `#FAF8F3` |
| 卡片与输入表面 | `#FFFFFF` |
| 聊天背景 | `#EEF0EB` |
| 品牌玉绿 | `#477964` |
| 品牌玉绿按下态 | `#3C6856` |
| 自己的消息气泡 | `#B8D9C6` |
| 主文字 | `#2A302D` |
| 次文字 | `#727A75` |
| 弱提示 | `#A4AAA6` |
| 分隔线 | `#E6E1D8` |
| 危险操作 | `#C95D57` |
| 提醒圆点 | `#D86A64` |

颜色统一通过 CSS 变量提供。现有绿色、灰色和边框硬编码逐步映射到变量，避免同一页面出现多套绿色。

### 5.2 字体与层级

- 延续系统中文字体栈，保证 Android WebView 的稳定性。
- 页面标题 17px/600；人物名称与主要列表标题 16–17px/600。
- 正文与聊天消息 15–16px；辅助信息 12–13px。
- 不使用大段全粗体；通过字号、色彩和留白区分层级。
- 行高保持 1.45–1.6，聊天长文本可舒适阅读。

### 5.3 圆角、间距与阴影

- 采用 4px 基础间距单位。
- 普通卡片圆角 14px；头像 12–14px；输入框 11–12px。
- 消息气泡 12px，并保留轻微方向特征。
- 列表以留白和细分隔线为主，不让每一项都变成悬浮卡片。
- 阴影仅用于浮层、底部抽屉和需要强调的卡片，普通列表不用重阴影。

## 6. 核心页面设计

### 6.1 消息、搜索与底部导航

- 顶栏使用暖白半透明表面，标题居中，左右操作位置保持不变。
- 消息列表背景为暖白，行高约 72px，虞栖头像采用玉绿基底。
- 搜索框使用白色表面、12px 圆角和弱提示文字。
- 未读提示使用低饱和陶红，避免刺眼。
- 底部导航继续保留“消息、通讯录、发现、我”，激活项使用玉绿。
- 后台记忆、同步和诊断不出现在消息列表。

### 6.2 聊天页

- 聊天区域采用 `#EEF0EB`，与顶栏和输入栏形成柔和分层。
- 对方气泡为白色；自己的气泡为浅玉绿色。
- 气泡文字保持高对比，最大宽度在窄屏为 76%，宽屏不超过 340px。
- 头像圆角统一为 10–12px。
- 时间、系统提示和输入中状态降低视觉权重。
- 输入栏为暖白底，文本框为白色圆角表面；发送按钮使用玉绿。
- 发送失败继续紧邻对应消息显示，保留“查看原因”和“重新发送”，但用统一的危险色和按钮状态。
- 表情、加号、语音和发送的位置与现有操作一致。

### 6.3 通讯录与人物资料

- 通讯录沿用字母索引和熟悉的纵向列表。
- 人物资料以头像、名字和关系信息为主，减少工具表单感。
- “发消息”保持最明确的主要操作。
- 高级人物配置收进折叠区域，不与人物基本资料争夺视觉注意力。

### 6.4 “我”、设置与维护页面

- “我”页面使用简洁资料头和分组列表。
- 通知、显示、聊天和隐私作为日常设置。
- 桥接、模型、记忆、诊断等现有入口归入高级维护层级；入口仍可找到，不在首页强调。
- 表单保持单列，标签和输入内容有清晰层级。
- 危险操作单独分组，并使用文字危险色；不大面积铺红。

### 6.5 发现、朋友圈、钱包与支付

- 发现页图标统一圆角、线宽和低饱和配色。
- 朋友圈封面降低深色渐变强度，头像和姓名保持清晰。
- 动态正文、图片、评论区使用同一套间距和次级文字颜色。
- 钱包与支付卡片使用玉绿作为识别色，但避免金融页突然切换成另一套视觉体系。

### 6.6 导入、安排表、记忆与诊断

- 功能结构和字段保持不变，只统一表单、卡片、分组标题和按钮。
- 文件导入区使用浅玉色虚线边框和明确操作说明。
- 安排表突出时间、状态和下一次执行，次要元数据降权。
- 记忆条目必须继续保留说话人、证据和来源，不通过视觉美化模糊归属。
- 诊断详情默认折叠；结果摘要使用普通语言，原始技术信息按需展开。

## 7. 组件与代码组织

当前前端主要集中在 `tavern-app/index.html`。本次采用低风险的渐进改造：

1. 扩展现有 `:root` 设计变量，建立暖色视觉令牌。
2. 在现有组件类上统一覆盖样式，复用当前 DOM、ID 和事件绑定。
3. 仅在无法可靠选择元素时增加表现用途的类名；不重命名或删除业务 ID。
4. 不改动 IndexedDB、消息发送、主动任务、导入和桥接数据流。
5. 保持 Android 打包仍从同一 Web 资源生成，避免 Web 与 APK 出现两套界面。

如果样式继续堆叠会产生明显冲突，可把纯视觉覆盖拆到独立 CSS 文件；拆分只服务于本次 UI，不进行无关重构。

## 8. 状态与交互反馈

- 所有可点击项提供按下态，但动画控制在 120–180ms。
- 加载状态不导致页面跳动。
- 禁用按钮同时通过颜色和交互状态表达，不只依赖透明度。
- Toast、弹窗和底部抽屉使用统一圆角、遮罩与安全区。
- 支持 `prefers-reduced-motion`，关闭非必要过渡。
- 键盘弹出后输入栏保持可见，聊天列表不被底部安全区遮挡。

## 9. 可访问性与适配

- 正文与背景达到可读对比度，弱提示也不得浅到无法识别。
- 主要触摸目标不小于 44×44px。
- 360px 宽度下不出现横向滚动；520px 容器下比例自然。
- 用户放大系统字体后，标题、表单和按钮允许增高，不裁切文字。
- 状态不能只通过颜色表达，错误和成功状态同时保留文字。

## 10. 验收标准

### 10.1 自动验证

- 现有全部前端、运行时、云端和 Android 测试继续通过。
- `screen-*` 页面 ID、关键按钮 ID和现有事件入口保持存在。
- 普通消息和主动消息流程不受视觉修改影响。
- 空用户消息、说话人归属和虞栖桥接来源约束继续通过。

### 10.2 视觉验证

至少检查以下视口：

- 360×800：常见窄屏 Android。
- 393×873：当前主流手机比例。
- 520px 宽：应用最大容器。

逐页检查 19 个现有页面：消息、搜索、聊天、聊天详情、通讯录、人物资料、发现、朋友圈、我、个人资料、设置、导入、安排表、阶段设定、记忆列表、记忆编辑、诊断、钱包和支付。

### 10.3 真机交互验证

- 从消息列表进入虞栖聊天并发送消息。
- 键盘弹出、连续消息、长消息和失败重试布局正确。
- 主动消息正常进入同一聊天。
- 进入人物资料、设置、高级维护、安排表和诊断后可正常返回。
- 页面滚动、底部抽屉、弹窗和 Android 返回键工作正常。
