# 虞栖主动私聊跳过预算设计

## 目标

解决主动私聊任务被聊天主脑与监督连续判定为 `skip`，导致云闹钟持续运行、任务持续成功，但用户长时间收不到任何正文的问题。

本轮只修复主动私聊的发送频率稳定性，不训练或固化用户潜台词，不根据“暂时不理你”“你自己去玩”等字面句式建立永久行为规则。潜台词理解留给后续人工标注训练。

## 已确认的故障模式

2026-07-26 的七次主动私聊中，五次最终为 `skip`，最近三次连续为 `skip`。部分任务由聊天主脑先返回空草稿，监督随后批准或再次选择跳过。系统把这些空结果当作成功提交和投递，因此调度链路看似正常，用户端却没有消息正文。

## 方案选择

### 方案 A：只调整预设

在提示词中要求模型更积极。实现简单，但模型仍可能连续跳过，无法提供可验证的频率上限。

### 方案 B：确定性跳过预算（采用）

由运行时根据历史任务结果计算跳过预算。模型仍决定内容和语气，但不能无限次选择沉默。

### 方案 C：完全禁止跳过

每次主动任务都必须发送。稳定性最高，但会使角色像定时客服，失去合理的沉默空间。

## 规则

1. 仅统计 `PROACTIVE_CHAT`，不影响朋友圈、角色计划、直接回复或支付行为。
2. 以角色为单位，检查玩家最近一次直接发言之后的主动私聊结果。
3. 最近四次已经提交的主动私聊中，最多允许一次 `skip`。
4. 玩家发送新的直接消息后，统计窗口自然重置。
5. 预算仍有余量时，聊天主脑可以选择 `skip`，监督可以批准。
6. 预算耗尽时，本轮输入明确携带 `skipAllowed: false`。聊天主脑必须生成一条符合当前生活、时间和关系状态的正文，可以分享小事、换话题、轻量试探或自然重新开口。
7. 如果聊天主脑仍返回 `skip`，运行时把它转成一次可执行返修，要求重新生成正文；不直接提交空结果。
8. 如果监督在预算耗尽时返回 `skip` 或 `reject`，运行时把决定转成 `rewrite`，并把具体返修要求交回聊天主脑。
9. 返修仍必须遵守事实、身份、时间、支付和元信息安全约束；频率稳定不能绕过硬性安全检查。
10. `skip` 仍是成功的内部决定，但不算一条已发送的主动消息，不写入聊天正文。

## 数据与接口

不新增可变计数表，避免手机、电脑和云端出现三份计数不同步。

运行时从现有 `turns` 记录派生：

- 最近玩家直接消息的时间；
- 此后最近四个已提交 `PROACTIVE_CHAT` 的 `reply_json.action`；
- 已使用的跳过次数；
- 本轮 `skipAllowed`。

聊天主脑与监督请求增加只读的 `deliveryPolicy`：

```json
{
  "kind": "proactive_chat",
  "windowSize": 4,
  "maxSkips": 1,
  "usedSkips": 1,
  "skipAllowed": false
}
```

该字段只约束是否必须形成正文，不规定角色应该如何理解用户，也不规定具体回复内容。

## 运行流程

1. 主动任务进入记忆阶段。
2. 运行时计算当前跳过预算。
3. 聊天主脑读取记忆、场景、生活状态和 `deliveryPolicy`。
4. 若允许跳过，沿用现有决策流程。
5. 若不允许跳过而主脑仍返回空草稿，运行时生成结构化返修要求并再次调用主脑。
6. 监督检查返修后的正文；预算耗尽时不得用 `skip` 代替可修正的回复。
7. 形成正文后正常提交、投递和续排。
8. 诊断记录保存窗口、已用额度、模型初始决定和最终决定，便于后台复核。

## 异常处理

- 数据库无法读取历史窗口时，采用保守默认：允许一次 `skip`，同时记录诊断，不阻断任务。
- 模型容量、网络失败和结构化输出错误沿用现有重试与模型切换机制，不消耗跳过预算。
- 只有最终提交为 `skip` 的任务才计入窗口；失败、取消、过期和被替代任务不计入。
- 预算耗尽后的返修不得使用固定兜底台词；必须由聊天主脑基于本轮上下文生成。

## 验收标准

1. 连续五次主动任务、玩家未发新消息时，最多一次最终为 `skip`。
2. 最近四次已有一次 `skip` 时，新任务返回 `skip` 会进入返修，而不是提交空结果。
3. 监督在禁止跳过时返回 `skip`，系统会把具体修改方向交回聊天主脑。
4. 玩家发来新的直接消息后，下一轮重新拥有一次跳过额度。
5. 朋友圈和角色计划的 `skip` 行为保持不变。
6. 不引入针对特定中文句式的硬编码判断。
7. 后台诊断能看见本轮跳过预算及最终处理结果。
