# 虞栖可靠异步桥接设计

日期：2026-07-19
状态：已确认，待实施

## 1. 背景与已证实问题

1. 正式 `yuqi-runtime` 健康检查显示三个角色线程已创建，但正式数据库没有任务、诊断或消息记录。截图中的回复因此不是专属小g链路产生，而是旧聊天 AI 回退回复。
2. 真实 Android 模拟器经 LAN 抵达隔离运行时后，记忆角色单步约耗时 130 秒；手机现有默认读取超时为 90 秒，最大值为 180 秒。三角色串行处理会使手机在专属小g完成前误判失败并回退。
3. 脑角色曾直接返回自然语言台词，而非运行时要求的 JSON，导致任务在 `brain_running` 阶段失败。
4. 主动消息与角色安排任务目前仍通过 `BridgeInput.userMessage()` 构造空用户消息，触发 `raw user message is empty`，并有污染说话人归属的风险。
5. Android 在桥接期间被系统回收后，`MEMORY_RUNNING` 状态会按旧本地“记忆 AI + 聊天 AI”流程恢复，而不是继续查询同一专属小g任务。

## 2. 目标

- 直接聊天、主动消息和角色安排都优先且真实地由专属小g完成。
- 保留三个独立角色线程：记忆、虞栖思考、发送前检查；模型与思考强度继续采用 `gpt-5.6-sol + high`。
- 手机提交任务后不依赖一条持续数分钟的 HTTP 长连接。
- 锁屏、切网、应用进程重启、LAN/Cloud 切换后继续取得同一个任务的结果，禁止重复生成回复。
- 只有专属运行时返回明确的最终失败，或达到可解释的总任务期限，才允许旧 AI 临时回退。
- 所有原始消息保留准确的 `speakerId`、`speakerType`、`origin` 和任务归属。
- 回退期间产生的真实消息在小g恢复后补入专属记忆，但不补发竞争回复。

## 3. 非目标

- 本次不改变虞栖人物设定和关系阶段规则。
- 本次不降低模型或思考强度来换取表面速度。
- 本次不把三个角色线程合并成一个聊天请求。
- 本次不在沉浸式聊天界面显示模型、提示词或内部角色名称。

## 4. 协议模型

### 4.1 协议版本

引入桥接协议 v2。v1 仅用于读取旧失败任务并转换为 v2 重试，不再用于新任务。

### 4.2 直接聊天任务

直接聊天必须携带真实用户消息：

- `kind = DIRECT_REPLY`
- `message.speakerId = user`
- `message.speakerType = user`
- `message.content` 非空
- 原始文本只保存一次，不能在重试或切换路由时重复写入。

### 4.3 自动任务

主动消息、moment 和角色安排使用 `trigger`，不构造用户消息：

- `kind` 为对应的自动任务种类；
- `triggerId` 唯一标识本次计划或云任务；
- `triggerType` 标识主动聊天、moment 或角色安排；
- `scheduledFor`、`executedAt` 和必要的计划上下文来自已冻结快照；
- 自动触发事件不写入 `messages` 表，也不作为用户证据参与记忆提取；
- 最终虞栖回复仍以 `speakerId = yuqi`、`speakerType = character` 写入消息库。

### 4.4 异步提交与查询

LAN：

1. `POST /v2/turns` 校验签名、幂等键和载荷，持久化任务后立即返回 `202 Accepted`。
2. 响应包含 `turnId`、当前状态、`accepted = true` 和建议查询间隔。
3. 运行时在后台处理三个角色；HTTP 请求结束不取消任务。
4. `GET /v2/turns/{turnId}` 使用新的时间戳、nonce 和签名查询状态。
5. 处理中返回稳定的公开状态；完成后返回唯一回复；最终失败返回稳定错误码和是否允许回退。

Cloud：

1. 手机到云信箱的加密任务保持幂等；电脑收到后按同一 v2 任务模型处理。
2. 手机进程可以多次查询同一 `turnId`，LAN 与 Cloud 路由切换不创建新任务。
3. 手机把一个已由 LAN 接收的 `turnId` 经 Cloud 再次登记时，电脑只为现有任务增加云端结果投递目标，不重新执行角色链路。
4. 电脑使用持久化结果 outbox：任务一旦提交或失败，所有已登记的云端投递目标都会收到同一终态；运行时重启后继续发送未确认的 outbox 项。
5. 云回复信箱按 `turnId + result checksum` 只写入一次；重复轮询只返回同一结果。

## 5. 状态与恢复

### 5.1 电脑端

- `POST` 只负责校验、保存和调度，不等待模型完成。
- 同一 `turnId + envelope checksum` 重复提交返回现有任务；校验和不同则拒绝冲突。
- 后台调度器维护进程内去重集合，同时以 SQLite 状态作为最终真相。
- 运行时重启后扫描非终态任务并按已保存检查点恢复：
  - 已有记忆结果则不重复提交记忆角色；
  - 已有脑草稿则不重复生成草稿；
  - 已有监督结果则继续提交或完成；
  - 某角色请求结果未知时，使用稳定 `clientUserMessageId` 恢复/去重，不生成第二条最终回复。
- 对外状态不暴露提示词、预设正文或角色内部思考。

### 5.2 手机端

- 桥接任务在 Room 中保持原有 `turnId` 和 attempt；网络中断不自动新建 attempt。
- `QUEUED` 首次提交；`MEMORY_RUNNING` 表示远端任务已提交或正在查询。
- 进程重启后，桥接任务从 `MEMORY_RUNNING` 重新提交同一幂等任务并继续查询，禁止转入旧本地模型流程。
- 每次 HTTP 查询使用较短的连接/读取超时；总任务期限独立计算，默认覆盖三角色高强度处理。
- 默认总任务期限为 20 分钟；每次切换网络或重启应用都沿用任务最初的期限，不能借重试无限延长，也不能把一次短连接超时误当作期限耗尽。
- 短暂超时、DNS、切网和应用后台化均为“继续查询”，不能触发 fallback。
- 只有远端明确 `failed_final`，或总期限耗尽且重试策略判定为最终失败，才进入 fallback。

## 6. 结构化角色输出

`turn/start` 为每个角色传入 Codex App Server 原生 `outputSchema`：

- 记忆角色：必须返回 `query`、`keywords`、`candidates`；
- 脑角色：必须返回 `reply`、`usedFactIds`；
- 监督角色：必须返回 `approved`、`issues`。

运行时仍保留本地语义校验：空回复、后台概念泄漏、证据引用错误和结构缺项均不得提交。结构化输出失败时允许在同一角色线程内进行一次有记录的协议修复；再次失败才标记该任务最终失败。

自动任务的记忆角色只检索既有事实与最近对话，不把 `trigger` 本身当作用户证据，也不从 trigger 文本生成“用户说过”的候选事实。脑角色接收字段名为 `currentTrigger`，不复用 `currentUserMessage`。

## 7. 回退与记忆补回

- fallback 必须记录 `origin = fallback`，专属回复记录 `origin = codex`。
- fallback 不能伪装成专属小g，也不能覆盖已经完成的专属回复。
- 回退日志按严格序号和校验和上传；小g恢复后由记忆角色读取真实原文并补记忆。
- 补回时继续执行说话人证据校验；用户原话不能挂到虞栖名下，虞栖原话不能挂到用户名下。
- 如果某回退任务已有可见回复，后续专属恢复只补记忆，不再向手机发送竞争回复。

## 8. 可观测性

每个任务至少记录：

- 路由尝试顺序；
- 接收、角色开始/结束、查询恢复、路由切换、终态时间；
- `origin`、`fallback`、稳定错误码；
- 手机 attempt 与电脑 `turnId` 的映射；
- 记忆补回的 ack 序号。
- 云端结果 outbox 的登记、发送和确认状态。

日志不得包含配对密钥、设备令牌、加密密钥、完整预设或内部思考文本。

## 9. 测试与交付门槛

### 9.1 自动测试

- Node：异步 `202`、幂等重复提交、冲突拒绝、状态查询、运行时重启恢复、结构化 schema 传递、无效结构重试、自动任务 trigger、说话人校验、回退补回。
- Node outbox：LAN 任务处理中登记 Cloud 投递、提交后投递、已提交任务立即投递、运行时重启续发、重复登记不重复写信箱。
- Android JVM/Room：长任务不会在 90 秒触发回退、`MEMORY_RUNNING` 进程恢复仍走桥接、LAN/Cloud 切换保持同一 turn、旧 `{}` 失败任务按新载荷重试、自动任务不生成用户消息。
- Worker/relay：重复拉取不重复回复、断网续取、云信箱幂等和 ack。

### 9.2 真实 Android 模拟器

必须在隔离数据库和隔离运行时中逐项通过：

1. 直接消息由 LAN 专属小g完成，来源为 `codex`；
2. 旧 `raw user message is empty` 任务更新载荷后重试成功；
3. 主动消息由 trigger 生成，电脑与手机库中都没有伪造用户消息；
4. 处理中终止并重启 Android 进程，恢复同一任务且只收到一条回复；
5. LAN 查询中断后经 Cloud 取得同一任务结果；
6. 模拟专属运行时最终失败，旧 AI 回退被明确标记；
7. 恢复后回退消息补入小g记忆，且不会补发第二条回复；
8. 双方原话、speaker、origin、时间和任务编号逐项一致。

### 9.3 交付规则

- 只有自动测试、真实模拟器端到端测试、手机 Room 数据检查、电脑 SQLite/诊断检查和备份检查全部通过，才生成并交付新版 APK。
- 不以“编译成功”“线程已创建”或单一单元测试代替端到端证明。
- 用户无需承担基础功能验证；交付时提供版本号、APK、验证项目和仍存在的明确限制。
