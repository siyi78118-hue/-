# 虞栖通用对话理解与活人感质量门设计

日期：2026-07-23  
基线提交：`7e9e681`（场景连续性恢复）

## 1. 目标

本次修复针对通用系统缺陷，不针对“废话废话”或任何单句建立关键词特判。系统需要在普通问答、玩笑、反话、撒赖、试探、调情、纠正、冲突、情绪表达和无目的闲聊中，稳定理解当前互动正在发生什么，并在保持速度的同时避免机械复述、评分、字面化承接和把话题责任全部推回用户。

同时必须保持以下边界：

- 不新增第四个角色窗口。
- 不把本轮可能的语用意图写成用户的长期人格事实。
- 原始消息仍是最高权威；语用判断只是带置信度的临时假设。
- 不让所有消息无条件进入深度通道或监督通道。
- 不回退 `7e9e681` 已完成的场景、关系阶段、红包和朋友圈连续性。

## 2. 已确认根因

生产记录显示，截图中的两轮均由聊天主脑直接生成，路线为 `fast`，没有经过监督。当前系统存在四个可复现的通用问题：

1. 路由只根据承诺、强情绪、纠正、文本长度等规则判断深度，无法识别短文本中的语用歧义和互动责任。
2. 记忆角色只整理可验证事实，不输出本轮交流行为的临时解释；聊天主脑只能自行从巨量输入中重新推断。
3. 当前消息既作为 `currentUserMessage` 单独提供，又包含在 `recentMessages` 中，形成重复强调。
4. 聊天角色长期复用同一 Codex 线程，同时每轮重新发送最多 200 条历史和完整预设，导致历史快照与旧生成模式不断重复累积。快速路线又直接发送草稿，使局部可通顺但整体机械的回复没有质量门。

## 3. 消息计数定义

当前 `contextLimit: 200` 以电脑端数据库中的 `message` 记录为单位：用户每次发送通常产生一条；虞栖一次生成的含换行回复在后台通常仍是一条，即使手机渲染为多个气泡。因此它既不等于 200 个可见气泡，也不等于 200 轮双方往返。

修复后分离两种窗口：

- 记忆证据窗口：最多 200 条，用于说话者归属、事实和承诺取证。
- 生成对话窗口：默认最近 24 条，并排除已单独提供的当前消息，用于聊天主脑和监督理解即时节奏。

更早内容只通过证据检索、关系阶段和持续状态进入生成上下文。

## 4. 临时 ConversationFrame

复用现有记忆小g调用，在其结构化结果中增加 `conversationFrame`。该对象随 turn 的 memory packet 保存用于恢复和诊断，但绝不进入事实表、向量记忆或用户画像。

建议结构：

```json
{
  "surfaceAct": "当前消息字面上完成的交流行为",
  "intentHypotheses": [
    {
      "intent": "一种可能的实际交流意图",
      "confidence": 0.0,
      "evidenceMessageIds": ["原始消息ID"]
    }
  ],
  "interactionMode": "当前互动形态，自由短标签而非固定场景枚举",
  "emotionalTone": "当前可观察语气，不诊断深层心理",
  "relationshipMove": "本句在当前关系中可观察到的作用",
  "initiative": {
    "topicIntroducedBy": "user|yuqi|shared|unclear",
    "suggestedNextCarrier": "user|yuqi|either|unclear",
    "reason": "基于最近原话的简短依据"
  },
  "activeHooks": ["可自然承接的原话或当前话题"],
  "ambiguities": ["不能确定且不得当成事实的解释"],
  "responseRisks": ["本轮普遍性的误读风险"],
  "needsNuanceReview": false
}
```

约束：

- 所有判断必须指向原始消息 ID。
- 不得输出诊断、隐藏人格结论或无证据动机。
- 多种解释并存时保留多个假设和置信度；聊天主脑以原文为准。
- `responseRisks` 描述失败类别，例如“只按字面承接”“忽略发起方责任”“把玩笑当事实”，不得硬编码具体回复词汇。

## 5. 数据流

### 5.1 用户直聊

1. 手机消息进入现有 durable turn。
2. 初始路由只决定记忆模型成本，不再独自决定最终是否监督。
3. 记忆小g读取证据窗口，输出事实候选、关系阶段复核和临时 `conversationFrame`。
4. 系统提交事实候选，但只把 `conversationFrame` 写入当前 turn 的 memory packet。
5. 若 `needsNuanceReview` 为真，或 frame 显示高歧义、说话者风险、关系风险、主动性错位，则把路线升级为 `fast_to_deep`，不重复运行记忆小g。
6. 聊天小g收到当前原文、24条去重短期窗口、interaction state、conversation frame、相关证据和场景关系阶段。
7. 普通明确回复直接提交；风险轮进入现有监督小g。监督也读取同一 frame，并只返回 `approve/rewrite/skip/reject`。

### 5.2 主动消息、朋友圈、红包和转账

沿用同一 conversation frame，但输入依据可以是 trigger、支付对象或朋友圈上下文。frame 不能把 trigger 伪装成用户原话，也不能改变已有结构化 action。现有支付、moment 和关系阶段字段保持权威。

## 6. 上下文去重与线程轮换

### 6.1 单轮去重

- `currentUserMessage` 存在时，生成窗口按 message ID 排除同一条记录。
- interaction state 可使用较宽的状态窗口，但聊天正文只使用短期生成窗口。
- 记忆小g继续使用证据窗口，避免降低说话者核验准确性。

### 6.2 长期线程控制

继续保留 memory、brain、supervisor 三个专属角色线程，但为每个线程持久化 turn count。达到 24 个模型 turn 后：

1. 串行完成当前角色调用。
2. 启动同角色的新 Codex thread 并将 session 指针切换过去。
3. 新线程第一轮仍携带完整预设、短期生成窗口、关系阶段和证据包，因此不会丢失关系连续性。

轮换只控制幕后上下文体积，不创建新的业务角色或第四个窗口。

## 7. 风险式质量门

不使用“合格”“进步”等单词黑名单，也不要求每条回复必须带新话题。通用风险来自：

- frame 对非字面含义存在中高置信度，而草稿只复述表面文字；
- 当前话题由虞栖发起且 frame 建议虞栖继续承担，但草稿只评价用户；
- 当前轮存在多个合理解释，草稿却把其中一个写成确定事实；
- 草稿与相邻虞栖回复高度重复，形成同一结构的自我强化；
- 草稿违反说话者、时间、关系阶段、支付或朋友圈结构化状态。

语义风险主要由 memory frame 决定是否进入监督；确定性结构错误继续由代码硬检查。监督发现问题时退回聊天主脑重写，直接私聊不得因活人感问题向用户显示技术错误。

## 8. 错误与恢复

- conversation frame 缺失或格式修复失败时，系统退化为当前原始消息＋短期窗口，不阻断回复。
- frame 低置信度时不强迫聊天主脑采用单一解释。
- 升级监督只改变后续阶段，不重复记忆抽取。
- Codex timeout 继续使用现有 transient requeue，从 memory checkpoint 恢复，frame 与已核实事实不重复生成。
- 线程轮换失败时继续使用原线程并记录诊断，不把失败暴露为虞栖聊天文本。

## 9. 测试策略

### 9.1 单元与流程测试

- 当前消息不会同时出现在 `currentUserMessage` 和生成窗口。
- 记忆仍可看到最多 200 条，聊天和监督只看到默认 24 条。
- conversation frame 随 memory packet 传到 brain/supervisor，但不会进入事实表。
- `needsNuanceReview` 能把 fast 升级为 `fast_to_deep` 且不重复记忆调用。
- 低置信度或缺失 frame 能安全退化。
- 专属线程达到上限后轮换，角色隔离与 session 恢复保持有效。

### 9.2 跨场景回归语料

用多类真实对话验证性质而非固定答案：

- 玩笑与认真话互相误判；
- 反话、否定、引用和纠正；
- 调情、撒赖、试探与边界；
- 虞栖发起话题后的主动性连续；
- 普通事实问答和无特殊含义的短回复；
- 情绪跨轮、长时间间隔、红包、朋友圈与主动消息；
- 同一句话由用户和虞栖分别说出时的归属。

模型评测不固定唯一文案，但必须检查：是否承接主要互动、是否过度读心、是否机械复读或评价、是否保持人物和场景连续、是否引用了有证据的事实。

## 10. 验收标准

- 不存在针对“废话”或某个截图文案的生产特判。
- 普通明确消息保持 fast 路径和现有速度级别。
- 语用高风险短消息可以自动进入监督，且不额外重跑记忆。
- 当前消息在生成输入中只出现一次。
- 聊天主脑输入不再包含 200 条完整历史。
- 临时语用判断不会污染长期记忆或用户画像。
- 全量运行时、前端和 Android 契约测试通过。
- 使用多类回归语料进行真实模型抽样，未出现说话者错置、结构化状态回退或系统信息泄漏。
