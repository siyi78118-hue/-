# Android 角色消息通知设计

## 目标

当角色消息真正生成完成时，AL 应立即发出系统默认提示音并震动，在锁屏界面直接显示角色昵称与消息正文。生成中的进度通知保持静音，后台守护通知也保持静音。

## 已确认代码现状与根因判断

- 当前最终消息和“正在生成角色消息”共用 `al_messages` 通知渠道。
- 代码只声明了高重要级别，没有显式声明默认提示音、震动和锁屏公开可见性。
- Android 8 及以上的通知渠道一经创建，声音、重要级别等关键设置由系统保存；App 升级后以相同渠道 ID 重新创建，不会覆盖手机中已有的旧配置。
- 因此，即使当前代码写着高优先级，手机仍可能继续使用早期保存的静音或锁屏隐藏配置。

## 通知渠道

### 最终角色消息

使用新的版本化渠道 ID，避免继承旧 `al_messages` 的不可变配置。

- 名称：`AL 新消息`
- 重要级别：高
- 声音：系统默认通知音
- 震动：开启
- 锁屏可见性：公开
- 通知正文：角色昵称和完整消息正文
- 通知类别：消息
- 点击行为：打开 AL；保留现有聊天定位能力，不引入全屏闹钟式界面

最终消息通知自身也显式设置公开可见性、默认声音和震动，兼容 Android 8 以下设备。

### 生成进度

新增独立的低重要级别静音渠道。

- 文案：`正在生成角色消息…`
- 无声音、无震动
- 不在锁屏展示消息正文
- 使用与最终消息相同的通知 ID；最终消息完成后替换进度通知

这样提示音只在真实回复完成时出现，不会在开始生成时提前响铃或连续响两次。

### 后台守护

继续使用现有低重要级别 `al_guard` 渠道，保持无声音、无震动，不改变常驻后台行为。

## 通知状态诊断

设置页诊断应报告以下状态：

1. Android 13 及以上的通知运行时权限是否获得。
2. AL 的应用级通知是否被系统关闭。
3. 最终消息渠道的重要级别是否为高、是否有声音。
4. 最终消息渠道声明的锁屏可见性是否为公开。

若系统阻止提示音或锁屏显示，提供跳转到 AL 系统通知设置页的入口。部分厂商不会向 App 暴露锁屏通知总开关的准确状态，此时诊断明确提示需要在系统页确认，不把未知状态报告为正常。App 不尝试绕过用户明确关闭的系统权限。

## 数据流

1. FCM、主动任务或普通聊天触发本地执行任务。
2. 任务进入生成阶段时，只发布静音进度通知。
3. 回复写入 Room 数据库并成为完成状态。
4. `AlExecutionService` 读取已落地的第一段有效回复文本。
5. 使用最终消息渠道发布通知，替换同一任务的进度通知。
6. 通知显示角色昵称与消息正文，并播放一次系统默认通知音、震动一次。

失败任务不得伪装成角色消息响铃；继续使用现有失败诊断或重试通知逻辑。

## 兼容与迁移

- 不删除旧渠道，避免修改用户系统设置；新版本不再向旧渠道发送最终角色消息。
- 新渠道使用新的固定 ID，确保本次升级获得正确默认配置。
- 用户之后若在系统设置中手动静音新渠道，AL 尊重该选择，不在每次启动时反复创建更多渠道。
- Android 8 以下通过 `NotificationCompat` 的声音、震动、优先级和可见性属性实现等效行为。

## 测试方案

### 自动化测试

- 新渠道 ID 与旧 `al_messages` 不同。
- 最终消息渠道为高重要级别、默认声音、震动开启、锁屏公开。
- 进度渠道为静音低重要级别。
- 最终消息通知为公开可见并包含角色昵称与正文。
- 进度通知和最终通知使用同一任务通知 ID，确保完成后替换而非叠加。
- Android 13 通知权限缺失时生成任务不崩溃。

### 真机验收

1. 手机亮屏且停留在其他应用：角色消息完成时响铃并显示横幅。
2. 手机锁屏：角色消息完成时响铃、震动，并显示角色昵称和正文。
3. 消息生成期间：可以看到进度通知，但不响铃、不震动。
4. 最终回复完成：进度通知被正式消息替换，只提醒一次。
5. 手动关闭消息渠道声音或锁屏显示：AL 诊断能识别，并可跳转系统通知设置。

## 非目标

- 不使用全屏 Intent，不把普通聊天伪装成电话或闹钟。
- 不绕过 Android 或手机厂商的用户通知设置。
- 本次不修改角色主动消息生成、消息同步和聊天内容逻辑。
