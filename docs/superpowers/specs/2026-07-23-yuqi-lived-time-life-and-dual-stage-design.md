# 虞栖真实时间、生活连续性、双轴关系阶段与幂等消息设计

日期：2026-07-23
基线提交：`55d739b`（虞栖通用对话理解）

## 1. 目标

本次改造同时解决四个已经在真实手机链路中复现的问题：

1. 同一个后台回复偶尔在聊天界面落地两遍。
2. 聊天中断十几分钟甚至更久后，虞栖仍像即时回复一样无缝续播上一幕。
3. 虞栖会解释自己的措辞、循环安抚或机械承接，用户离线期间也没有持续推进的生活和自然反应。
4. 分阶段人设虽然已经传入主脑，但自动关系审查持续以高置信度保持“初识”，没有实际升级、降级或矛盾阶段。

目标不是增加针对某张截图或某个词的特判，而是建立可观测、可持久化、可监督、可回归测试的通用状态链路。

## 2. 已确认根因

### 2.1 重复回复

真实任务 `turn_msg_1784787954289_vsozbk` 在电脑数据库中只有一个角色消息，云端投递次数为一次且已经确认。重复发生在手机界面应用完成结果时。

手机界面可从提交回调、三秒轮询、前台恢复和未应用完成箱同时进入 `applyNativeExecutionTurn`。该函数在去重判断前先等待异步计划处理。两个并发调用可以同时越过等待、同时看到“尚未显示”，随后分别追加一组气泡。现有随机气泡 ID 无法阻止第二次插入。

### 2.2 时间间隔

本轮用户消息在记忆阶段前已经写入数据库。`buildAuthoritativeInteractionState` 直接从完整消息列表取最后一条，因此把本轮用户消息当成“上一条消息”。`silenceMsSinceLastMessage` 实际表示模型处理本轮消息用了多久，而不是聊天在本轮开始前中断了多久。

处理延迟与会话间隔是两个不同概念，必须分别计算：

- `processingDelayMs`：当前消息发出到虞栖准备回复之间的时间。
- `conversationGapMs`：当前这一批消息开始前，上一段聊天最后一条消息到本批消息之间的时间。

### 2.3 活人感

当前系统有角色预设和临时 `conversationFrame`，但没有持久的虞栖生活状态。每一轮只能从静态职业和最近文字重新猜测她在做什么、心情如何、注意力在哪里。生成结果容易在“完全冻结”和“随口编一个新活动”之间摆动。

监督层也没有明确拒绝以下通用失败：

- 像分析报告一样解释自己刚才某个词的含义；
- 围绕同一个担忧重复澄清，没有新的关系动作；
- 话题未结束且经历明显中断，仍按即时上下句无缝续播。

### 2.4 关系阶段

真实记录证明手机已把完整阶段目录传给运行时，主脑也收到“初识”。但运行时记忆预设没有完整的自动阶段评估标准，模型连续返回 `new → new` 且置信度约 `0.99`。阶段解析和手机写回管道存在，却从未获得变更动作。

现有单轴阶段也无法表达“已经熟悉，但正在闹矛盾”。把矛盾简单当成亲密程度下降，会错误抹掉已经存在的共同历史。

## 3. 总体架构

系统保留现有记忆小 G、聊天小 G、监督小 G，不新增第四个角色窗口。每轮数据流调整为：

1. 手机提交当前批次消息 ID 和动态场景。
2. 运行时排除当前批次后计算真实会话间隔。
3. 记忆小 G 同时输出事实候选、当前互动框架、话题收束判断和双轴关系复核。
4. 运行时代码验证证据，解析长期关系和当前相处阶段动作。
5. 离线生活模拟器把持久时间线推进到当前时刻；缺少后续生活片段时由聊天小 G 兼职规划，监督小 G 审核。
6. 聊天小 G 读取真实时间、当前生活片段、近期生活轨迹、话题状态和双轴阶段，输出正文及必要的生活调整。
7. 监督小 G 对时间冻结、元解释、安抚循环、生活状态越界和阶段错位进行审查。
8. 只有批准后的回复、生活事件和阶段动作才能提交。
9. 手机以单航班协调和确定性气泡 ID 幂等应用结果。

## 4. 真实会话间隔与话题连续性

### 4.1 当前批次边界

直聊 envelope 的 `context` 增加：

```json
{
  "currentBatch": {
    "batchId": "batch_xxx",
    "messageIds": ["msg_a", "msg_b"],
    "startedAt": 1784786372581,
    "committedAt": 1784786374877
  }
}
```

普通单条消息同样使用一个消息 ID 的批次。Android 桥从现有 `options.batchMessageIds` 复制该信息，禁止靠相同时间戳猜测批次。

### 4.2 InteractionState

`buildAuthoritativeInteractionState` 先排除当前批次，再生成：

```json
{
  "processingDelayMs": 64000,
  "processingDelayText": "1分钟",
  "conversationGapMs": 1200000,
  "conversationGapText": "20分钟",
  "conversationGapClass": "interrupted",
  "previousMessageId": "msg_previous",
  "previousSpeakerId": "yuqi",
  "previousMessageContent": "上一段最后一句",
  "currentBatchMessageIds": ["msg_a", "msg_b"]
}
```

间隔级别：

- `continuous`：少于 3 分钟；
- `brief_pause`：3 分钟至不足 10 分钟；
- `interrupted`：10 分钟至不足 1 小时；
- `long_interruption`：1 小时至不足 24 小时；
- `new_day`：跨日或至少 24 小时。

级别只提供时间事实，不直接决定文案。

### 4.3 话题状态

`conversationFrame` 增加：

```json
{
  "priorTopic": {
    "status": "closed|open|uncertain",
    "summary": "上一段仍在进行的互动",
    "waitingOn": "user|yuqi|either|none|unclear",
    "evidenceMessageIds": ["msg_previous"],
    "reason": "基于原话的简短依据"
  },
  "interruption": {
    "requiresReaction": true,
    "reactionReason": "话题未结束且用户离开了20分钟"
  }
}
```

规则：

- 已收束话题不因经过十分钟而强制报时或解释中断。
- 未结束话题跨过 `interrupted` 边界时，回复必须重新站在当前时刻判断。
- 反应可以通过注意力变化、情绪余波、已经转去做别的事、重新开口或不再追问表现，不要求机械说出具体分钟数。
- `uncertain` 不强迫唯一解释，但禁止把角色冻结在上一秒。

## 5. 持久运行的离线生活模拟

### 5.1 核心原则

虞栖的生活不在用户发送消息时才临时生成。运行时维护一条独立于聊天窗口的角色生活时间线：用户不说话时，工作、吃饭、通勤、休息、娱乐、睡眠、注意力、疲劳和轻微情绪仍会继续推进。

模拟不按分钟调用模型。代码状态机负责时间推进和事件切换；聊天小 G 兼职规划未来数小时的低风险生活片段，监督小 G 审核后持久化。这样既有真实连续性，也不会因频繁随机生成而漂移。

### 5.2 数据模型

运行时增加 `life_episodes` 事件表和 `character_life_state` 当前状态表。

生活片段示例：

```json
{
  "episodeId": "life_yuqi_20260723_work_03",
  "characterId": "yuqi",
  "kind": "work",
  "summary": "通读刚改完的文案",
  "attention": "工作为主，偶尔看手机",
  "mood": "略疲惫但不烦躁",
  "socialEnergy": "medium",
  "plannedStartAt": 1784788800000,
  "plannedEndAt": 1784794200000,
  "actualStartAt": 1784788800000,
  "actualEndAt": null,
  "status": "active",
  "basis": "explicit|carryover|routine|role_plan",
  "basisMessageIds": ["msg_yuqi_xxx"],
  "sourceTurnId": "turn_life_yuqi_xxx",
  "visibility": "private|shared",
  "confidence": 0.82
}
```

当前状态只保存正在进行的片段、未解决互动、心情余波、疲劳、注意力和规划视野终点。完整轨迹保存在事件表，避免把所有历史塞进每轮 prompt。

### 5.3 规划与推进

生活协调器使用三种机制：

1. **预规划**：当未来已批准生活片段不足六小时时，聊天小 G 以 `plan_yuqi_life` 任务输出接下来六至十二小时的片段。
2. **后台推进**：现有运行时定时循环在片段边界推进状态，不需要每分钟调用模型。
3. **懒惰补算**：服务重启、电脑休眠或网络中断后，处理任何聊天、主动消息或朋友圈任务前，先从最后检查点补算到当前时刻。

规划输入包括角色稳定身份、时区、星期与时段、已批准生活轨迹、角色安排表、当前疲劳和心情、未解决互动以及双轴关系状态。随机选择使用 `characterId + 日期 + 规划版本` 的稳定种子，相同状态重放得到相同结果，恢复任务不会生成另一套生活。

片段持续时间以十几分钟至数小时为单位。状态机禁止时间重叠、倒退、无解释瞬移和无限延长短时活动。

### 5.4 日常事件边界

允许模拟并成为虞栖世界内真实经历的低风险日常包括：

- 工作、审稿、改文案、沟通普通工作事项；
- 吃饭、喝茶、通勤、散步、买普通日用品；
- 打游戏、追剧、刷视频、阅读、发呆和休息；
- 睡觉、起床、疲惫、走神、轻微烦躁或心情变好；
- 与未具名朋友或同事的普通社交，但不能凭空制造重要新关系。

禁止自动生成：

- 事故、疾病、违法、失业、处分、巨额损失等重大事件；
- 具体可识别的新人物、恋爱对象、背叛或家庭危机；
- 改写角色长期身份、住址、职业、经济状况和核心经历的事实；
- 仅为制造戏剧性而出现的冲突。

重大事件只能来自用户明确共同经历、人工角色设定、已批准安排表或后续专门授权。

### 5.5 未结束互动进入生活时间线

上一话题为 `open` 时，生活状态保存一条 `openInteraction`：

```json
{
  "summary": "虞栖在等用户回应是否还想继续聊",
  "waitingOn": "user",
  "startedAt": 1784787950000,
  "evidenceMessageIds": ["msg_previous"],
  "emotionalCarry": "轻微在意",
  "status": "waiting"
}
```

生活继续推进时，未解决互动可以：

- 保持等待；
- 因注意力转移而降低强度；
- 因持续失联、矛盾或重要承诺而增加在意；
- 被新的用户消息、明确结束或双方修复解决。

时间只能改变强度和当前表达，不能凭空判定用户动机，也不能自动把矛盾清零。

### 5.6 跨场景共享

直聊、主动消息、朋友圈和角色安排表使用同一生活时间线：

- 直聊读取当前片段和最近三段轨迹。
- 主动消息只有在当前生活、未解决互动或新念头形成真实动机时才发送，否则 `skip`。
- 朋友圈只能从已发生且适合公开的生活片段产生，不得另编一套当天经历。
- 安排表形成的生活片段优先于普通例行规划；冲突时重新规划未开始片段。

生活事件本身不能直接推动关系升级或降级。长期关系和矛盾阶段仍只能依据双方可验证的互动证据变化。

### 5.7 用户互动对生活规划的影响

用户消息可以影响虞栖的生活时间线，但不能直接改写时间线。流程必须是“用户提出或影响 → 虞栖作出自己的决定 → 监督核对正文与决定 → 原子提交生活调整”。

影响分为四类：

1. **明确共同约定**：用户提出“晚上一起打游戏”，虞栖明确答应后，新增有证据的共同安排；没有答应就不能写入。
2. **即时打断或邀请**：用户说“现在陪我聊会儿”，虞栖可以暂停、缩短、延后原活动，也可以因为正在忙而拒绝或稍后再聊，结果由性格、当前活动、关系阶段和意愿决定。
3. **软性影响**：用户推荐电影、奶茶或散步地点，可以形成兴趣候选并在未来娱乐、饮食片段中提高出现概率，但不能立刻假定虞栖已经去做。
4. **情绪与注意力影响**：聊天、冲突、关心、承诺或失约可以改变心情、社交精力、注意力和未解决互动；影响强度必须有原话证据并随时间合理变化。

正常回复可输出：

```json
{
  "lifeAdjustment": {
    "operation": "none|interrupt|shorten|extend|reschedule|add|cancel",
    "targetEpisodeId": "life_yuqi_xxx",
    "episode": null,
    "reason": "虞栖为什么愿意或不愿意改变原计划",
    "evidenceMessageIds": ["msg_current"],
    "acceptedByYuqi": true
  }
}
```

约束：

- 用户请求本身不是生活事实，只有虞栖明确接受的决定才能调整时间线。
- 正文说“好，晚上一起玩”时必须有对应 `add/reschedule`；正文拒绝时必须为 `none`。
- 时间线调整与聊天回复原子提交，不能出现嘴上答应但安排未写入，或安排已改变但正文仍拒绝。
- 新安排与已有工作、睡眠、角色计划冲突时，虞栖必须选择拒绝、改时间或明确替换；代码不允许静默覆盖。
- 用户不能通过连续要求把虞栖永久变成待命状态，监督继续检查 `ALWAYS_AVAILABLE`。

### 5.8 聊天小 G 与监督职责

聊天小 G 增加两个结构化任务：

- `plan_yuqi_life`：规划未来生活片段，不生成聊天正文。
- 正常回复中的 `lifeAdjustment`：只在当前消息真实打断、延长或改变正在进行的片段时调整时间线。

监督小 G 检查时间覆盖、活动合理性、重大事件边界、前后矛盾和是否为了迎合用户让虞栖一直待命。规划未通过时保留原时间线并重写，不能把未批准片段当成既成事实。

监督同时检查正文与 `lifeAdjustment`。新增 `PLAN_REPLY_MISMATCH`：聊天正文中的答应、拒绝、改期与实际生活调整不一致。

### 5.9 活人感质量门

监督新增通用问题代码：

- `TEMPORAL_FREEZE`：开放话题跨越明显间隔后仍像即时回复。
- `META_EXPLANATION`：不必要地分析自己或用户的措辞，而不是参与互动。
- `REASSURANCE_LOOP`：重复解释或安抚同一件事，没有新的当下反应。
- `LIFE_STATE_CONTRADICTION`：当前活动、时间、情绪与已批准生活轨迹冲突。
- `LIFE_STATE_FABRICATION`：无依据创造重大或禁止的外部经历。
- `LIFE_TIMELINE_OVERLAP`：生活片段重叠、倒退或出现无解释瞬移。
- `ALWAYS_AVAILABLE`：生活规划长期围绕用户待命，没有角色自己的活动和注意力。
- `PLAN_REPLY_MISMATCH`：正文中的生活承诺、拒绝或改期与时间线调整不一致。
- `RELATIONSHIP_STATE_MISMATCH`：正文与长期关系程度或当前相处阶段冲突。

问题代码描述失败性质，不规定唯一回复文案。

## 6. 双轴关系阶段

### 6.1 长期关系程度

保留现有五级：

1. `new`：初识
2. `acquainted`：认识
3. `familiar`：熟悉
4. `close`：亲近
5. `committed`：关系确立

长期程度允许自动升级和自动降级。

升级依据包括双方持续投入、稳定联系、私人日常分享、共同梗、主动关心、边界放宽和明确关系表达。降级依据包括持续疏远、长期回避、反复伤害、信任破裂、明确撤回关系或双方形成的新边界。

普通变化只能相邻一级；明确确立、分手、绝交等双方可验证行为允许跨级。消息数量、一次红包、一次玩笑、单方面称呼和短暂争执不能单独触发长期变化。

### 6.2 当前相处阶段

新增默认阶段目录：

- `normal`：正常相处
- `awkward`：别扭期
- `conflict`：闹矛盾期
- `cooling`：冷静期
- `repairing`：修复期

当前阶段与长期程度组合显示，例如：

- `熟悉 · 闹矛盾期`
- `亲近 · 冷静期`
- `关系确立 · 修复期`

进入矛盾阶段需要持续冲突、未解决伤害、明显回避或双方承认矛盾等证据；一次拌嘴不足以触发。修复必须有道歉、解释、重新投入、边界协商或实际和好证据，不能只因时间流逝自动恢复正常。

### 6.3 结构化审查

记忆角色输出：

```json
{
  "relationshipReview": {
    "base": {
      "current": "familiar",
      "recommended": "familiar",
      "confidence": 0.91,
      "reason": "长期熟悉基础仍然存在",
      "evidenceMessageIds": ["msg_1", "msg_2"],
      "explicitMutualChange": false
    },
    "phase": {
      "current": "normal",
      "recommended": "conflict",
      "confidence": 0.88,
      "reason": "冲突持续且尚未解决",
      "evidenceMessageIds": ["msg_3", "msg_4"]
    }
  }
}
```

运行时代码验证阶段 ID、相邻变化、置信度、证据存在性和明确关系行为。模型不能自由创建阶段 ID。

### 6.4 手机写回

`RELATIONSHIP_STAGE` reply part 同时携带可选 `baseAction` 和 `phaseAction`。手机在同一事务式应用中更新两轴、变更原因、证据和历史。旧版仅含 `from/to` 的动作继续兼容。

阶段编辑页增加长期阶段和当前相处阶段两个选择器，支持手动调整、编辑阶段文案、查看历史和撤销。联系人与聊天信息页显示组合标签。

## 7. 回复幂等落地

### 7.1 单航班协调

所有 `reconcileNativeExecutionTurns` 调用共享一个进行中的 Promise。轮询、前台恢复和提交回调若同时触发，只加入同一轮协调，不并发遍历完成箱。

每个 `turnId` 另有应用级单航班，确保计划动作、阶段动作、生活状态和聊天消息按一条串行路径落地。

### 7.2 确定性气泡 ID

每个文本分片拆出的气泡使用：

```text
native_<turnId>_<replyPartId>_<chunkIndex>
```

插入前按确定性 ID 检查。即使进程恢复、游标重放、完成箱重放或旧代码路径绕过单航班，同一气泡仍只能存在一份。

支付卡、朋友圈、计划和阶段动作继续使用各自稳定业务 ID。只有全部预期界面结果已落地后才确认 `acknowledgeUiApplied`。

## 8. 错误与兼容

- 缺少 `currentBatch` 的旧 envelope 退化为仅排除当前消息，并记录诊断。
- 缺少生活状态时从空状态开始，不阻断回复。
- 生活状态输出格式错误时保留上一状态并要求重写；不得让正文丢失。
- 关系审查缺失或证据不足时保持当前两轴，不伪造变化。
- 老版单轴阶段数据迁移为原长期阶段加 `normal`。
- 老 APK 收到仅有旧式 `from/to` 的动作仍能工作；新 APK 能读取旧历史。
- 幂等检查发现同一确定性 ID 内容不同必须记录冲突，保留首次已确认内容，不能显示两份。

## 9. 测试策略

### 9.1 重复落地

- 两个并发协调调用应用同一个已完成 turn，只生成一组气泡。
- 提交回调与未应用完成箱并发，只应用一次。
- 应用重启后重放同一 turn，确定性 ID 阻止重复。
- 同一分片拆成多个气泡时，每个 chunk 独立幂等。
- ID 相同但内容不同记录冲突，不覆盖首次内容。

### 9.2 时间与话题

- 当前消息和当前批次不会进入“上一段聊天”计算。
- 真实 20 分钟间隔不会被 40 秒处理耗时覆盖。
- 已收束话题经过 20 分钟不强制时间反应。
- 开放话题且用户中断 20 分钟时，`requiresReaction` 为真。
- 批量发送的多条用户消息属于同一当前批次，不把彼此误算为历史间隔。
- 处理延迟和会话间隔分别传给记忆、主脑和监督。

### 9.3 离线生活模拟与活人感

- 固定时钟和稳定种子下，生活规划与重放结果确定一致。
- 用户离线三小时后，时间线跨越多个生活片段并停在正确当前状态。
- 服务重启和电脑休眠后能从检查点补算，不能重叠或重复创建事件。
- 已批准的普通生活片段能跨轮、直聊、主动消息和朋友圈共享。
- 被重写或拒绝的规划不能提交。
- 角色安排表与普通规划冲突时，未开始片段被安全重排。
- 用户邀请只有在虞栖明确接受后才创建或调整生活片段。
- 正文接受共同安排但缺少对应生活调整时触发 `PLAN_REPLY_MISMATCH`。
- 用户软性推荐只提高未来候选概率，不会被立即当作已经发生。
- 虞栖拒绝即时邀请时，原生活片段保持不变。
- 开放互动的情绪余波能随生活推进变化，但不能无证据判断用户动机。
- 重大无证据经历触发 `LIFE_STATE_FABRICATION`。
- 元解释、安抚循环和时间冻结进入监督重写。
- 普通直接回答不会因活人感规则被强迫添加行程报告。
- 连续多日模拟不会让虞栖一直围着用户待命。

### 9.4 双轴阶段

- `new → acquainted` 在有足够双方互动证据时可自动发生。
- 一次友好消息、红包或单方面亲昵称呼不会升级。
- 持续疏远可使长期程度相邻降级。
- `familiar · normal` 可进入 `familiar · conflict`，长期程度不被抹掉。
- 一次拌嘴不会进入冲突期。
- 有修复证据后可进入 `repairing`，无证据不能按时间自动清零。
- 阶段动作写回手机后，下一轮 envelope 使用新组合状态。
- 手动调整、撤销与旧数据迁移保持可用。

## 10. 验收标准

- 真实完成任务无论通过多少入口重放，手机聊天中每个气泡最多出现一次。
- 后台一条角色消息不会在手机显示成两组相同气泡。
- `conversationGapMs` 与 `processingDelayMs` 在诊断中可分别观察。
- 开放话题经过十分钟以上中断后，不再出现无缝即时续播。
- 已结束话题不会被机械加上报时、道歉或“刚看到”。
- 虞栖离线期间的普通生活会持续推进，重启后可补算，并被直聊、主动消息和朋友圈共同使用。
- 已发生生活片段能成为后续连续世界状态，但不会无证据制造重大经历。
- 用户互动可以通过虞栖自己的决定改变未来规划；回复承诺与时间线调整始终一致。
- 监督能够拒绝时间冻结、元解释、循环安抚和阶段错位。
- 关系阶段可以基于真实证据自动升级、自动降级，并独立进入矛盾、冷静和修复阶段。
- 手机能够显示、编辑、记录和撤销双轴阶段。
- 运行时、前端契约、Android 单元测试和构建全部通过。
