# AL 角色自主计划与安排表设计

## 目标

让角色在聊天中自主创建、修改、取消和完成未来计划。计划到期后，Android 原生执行链能够在应用位于前台、后台、锁屏或进程被回收时可靠执行，并结合最新聊天、记忆和角色日程重新生成私聊或朋友圈内容。

典型场景：角色说“我明天早上九点起床后给你发早安”，软件静默保存计划；次日九点云端唤醒手机，角色回想原始承诺及最新对话后主动发送自然的早安消息。

## 已确认的产品规则

- 明确承诺自动创建计划，不在聊天界面显示创建提示。
- 计划统一显示在“角色设置 → 安排表”。
- 后续继续聊天不会自动取消承诺；只有角色明确取消、改期、出现明确事实冲突，或用户在安排表操作时才改变计划。
- 支持一次性和周期计划，时间跨度不设上限。
- 支持主动私聊、发布朋友圈和仅记录不发送的角色日程。
- 角色日程会成为聊天 AI 的当前状态上下文；不再成立的日程应自动取消或结束。
- 模糊时间由 AI 根据角色作息和现有日程推定，并标记为“AI 推定时间”。
- 所有计划按手机当前时区解释；重复计划跟随手机本地时间。
- 私聊和朋友圈到点后结合最新上下文重新生成，不提前写死正文。
- 角色可以创建已经说出口的计划，也可以创建“角色私下决定”的隐藏计划；两者都可在安排表查看。
- 每个角色最多同时保留 50 个有效计划。

## 总体架构

新增独立的角色计划系统，不复用现有每角色单一的普通主动私聊和朋友圈任务。

```text
聊天 AI 生成正文和隐藏计划操作
→ 本地计划引擎验证、解析、去重和持久化
→ 云端登记每个有效计划的下一次最小化唤醒任务
→ FCM 到点唤醒 Android 原生执行链
→ 原生领取唯一执行期次
→ 读取计划、最新聊天、记忆和角色日程
→ 生成私聊/朋友圈，或更新日程状态
→ 持久化结果并确认云端任务
→ 周期计划登记下一期
```

### 数据权威与隐私边界

- 完整计划、原始承诺、创建依据、计划目的和历史只保存在设备本地。
- Android 使用 Room 作为权威存储；网页环境使用 IndexedDB 兼容存储。
- Cloudflare 只保存设备 ID、计划 ID、角色 ID、任务类型、期次 ID 和下一次触发时间。
- 云端不保存聊天正文、记忆、角色完整日程、系统提示词或 API Key。
- 普通主动任务继续保留现有单任务规则；`role-plan` 使用独立任务类型，允许同一角色存在多个计划。

## 计划模型

每条计划至少包含：

- `planId`：本地稳定唯一 ID。
- `characterId`：所属角色。
- `type`：`private_message`、`moment_post` 或 `role_schedule`。
- `origin`：`ai` 或 `user`，区分 AI 自动计划与用户在安排表手动创建。
- `source`：`spoken`、`private_decision`、`accepted_request` 或 `user_created`。
- `title`：安排表中的简短标题。
- `intent`：到点时要实现的目的，不是预写消息正文。
- `schedule`：一次性时间或重复规则。
- `timezoneMode`：固定为 `device_local`。
- `timeConfidence`：`explicit` 或 `inferred`。
- `nextRunAt`：下一次绝对执行时间。
- `status`：`active`、`paused`、`running`、`completed`、`cancelled` 或 `failed`。
- `evidenceMessageIds`：创建或修改依据的消息 ID。
- `sourceQuote`：经过长度限制和脱敏的角色原话摘要。
- `createdAt`、`updatedAt`、`completedAt`、`cancelledAt`。
- `lastOccurrenceId`、`lastRunAt`、`lastResult`、`lastErrorCode`。
- 对角色日程额外保存可选的 `endsAt` 和状态区间。

计划修改记录使用追加式历史，记录操作类型、旧值摘要、新值摘要、依据消息和时间。AI 自动删除表现为取消并进入历史，不直接物理删除。

## AI 隐藏计划协议

聊天 AI 可在正常回复末尾输出一个 `<al_plan>` JSON 区块。该区块不会展示在聊天气泡中，也不得进入普通消息正文。

```xml
<al_plan>{
  "operations": [
    {
      "op": "create",
      "type": "private_message",
      "source": "spoken",
      "title": "起床后发早安",
      "intent": "明天起床后主动向用户问早安",
      "schedule": {
        "kind": "once",
        "at": "2026-07-17T09:00:00"
      },
      "timeConfidence": "explicit"
    }
  ]
}</al_plan>
```

支持的操作：

- `create`：创建新计划。
- `update`：修改现有计划时间、目的或重复规则。
- `cancel`：明确取消现有计划。
- `pause` / `resume`：暂停或恢复周期计划。
- `complete`：确认日程或计划已经完成。

`update`、`cancel`、`pause`、`resume` 和 `complete` 必须引用现有 `planId`。生成回复时，模型会收到经过长度限制的有效计划目录（计划 ID、标题、类型、下一次时间和状态），以便引用正确目标。目标不存在时记录诊断，不对其他计划做模糊修改。

### 计划判断规则

- 明确承诺、答应的用户请求和角色私下决定均可创建计划。
- “不想上班”不是取消；“明天不上班了”可取消对应单次日程；“我辞职了”可取消或暂停未来相关重复日程。
- 取消、改期和事实冲突必须具有明确语义或明确引用依据。
- 修改已有语义相同计划，不能重复创建。
- 隐藏指令解析或验证失败不影响正常聊天回复，只写入脱敏诊断。

## 时间与重复规则

支持：

- 一次性绝对或相对时间。
- 每天指定本地时间。
- 每周指定星期和时间。
- 每月指定日期和时间。
- 固定时间间隔。
- 具有开始时间和可选结束时间的自定义周期。

规则：

- 所有自然语言时间最终转换为手机当前时区下的结构化规则。
- “明天早上九点”为明确时间；“晚点”“下班后”为 AI 推定时间。
- AI 推定时间须结合角色现有日程、作息和当前时刻，并在安排表标记。
- 用户后续提供更精确时间时更新原计划。
- 一次性过去时间无效；周期规则必须能计算出未来期次。
- 主动私聊和朋友圈计划最短间隔为 5 分钟。
- 每个周期计划只向云端登记下一期，不预先写入全部未来期次。
- 重复任务跟随设备本地时间。设备时区变化后重新计算尚未领取的下一期；已领取期次不重复执行。

## 安排表

在每个角色设置页面增加“安排表”入口，包含：

- 即将执行：按 `nextRunAt` 排序。
- 周期安排：每天、每周、每月和自定义周期。
- 角色日程：当前进行中和未来日程。
- 历史记录：已完成、已取消、被替换和失败任务。

每条计划显示标题、类型、来源、下一次时间、重复规则、明确/推定时间、状态及最近执行结果。

用户可以新建、编辑、暂停、恢复、立即执行、取消、重试本期、查看依据与历史，以及删除已完成历史。修改计划正文指修改 `intent`，不会预写最终聊天消息。

## 角色日程上下文

角色日程不主动发送内容。到达开始或结束时间时只更新结构化状态，并使用独立幂等期次。

聊天 AI 仅接收与当前时间相关的有效日程摘要，例如：

```text
当前角色状态：
09:00 已起床
10:00–18:00 上班
20:00 与朋友吃饭
```

已取消、已结束或与最新事实冲突的日程不得继续进入提示词。长期稳定事实如职业变化仍由现有记忆系统保存；安排表只表达可执行、可变更的日程实例或重复安排。

## 到点生成

到点生成私聊或朋友圈时，模型输入包含：

- 计划 ID、类型、来源、目的和创建依据。
- 原定执行时间、实际执行时间和迟到时长。
- 最新聊天内容与未完成的玩家手动消息状态。
- 与计划直接相关的长期记忆。
- 当前有效角色日程。
- 最近相似发送记录，用于避免复读。

模型只生成当时自然应发送的内容，不向用户解释闹钟、计划系统或隐藏指令。明确承诺即使后续继续聊天仍执行，除非计划已明确取消或改期。

## 执行优先级与可靠性

优先级从高到低：

1. 玩家手动消息的待回复任务。
2. 明确承诺或答应请求的计划私聊/朋友圈。
3. 角色私下决定的计划。
4. 普通计划追发和随机主动消息。

每次执行使用 `planId + occurrenceTime` 生成稳定 `occurrenceId`。本地领取必须原子化，确保重复 FCM、前后台同时检查、应用重启或 Worker 重投均不能重复执行同一期。

执行顺序为：领取期次、生成、持久化结果、应用到 UI 收件箱、确认云端、计算下一期。周期计划只有在本期结果成功持久化后才推进。

手机离线时保留待执行状态；网络恢复后补执行。生成提示明确提供原定时间和实际时间，使角色能够自然处理延迟。

### 失败处理

- 网络超时、临时 5xx 和连接中断按有限次数退避重试。
- API 余额不足、模型无权限、配置缺失等确定性错误暂停本期并显示在安排表，不无限重试或刷日志。
- 用户修复配置后可“重试本期”。
- 生成成功但 WebView 未加载时，结果保存在原生收件箱；进入应用后应用结果，不重新调用 AI。
- 云端登记失败保留本地计划与待同步状态，后续前台同步或后台保护服务补登记。
- 取消、暂停和改期同步撤销旧云端任务；旧 FCM 到达时通过 plan/occurrence 校验拒绝。

## 云端任务规则

- 新增 `type: role-plan`，以 `jobId` 独立存储，不参与现有每角色/类型的普通主动任务单例替换。
- 云端载荷只包含执行所需的最小标识，不携带计划 `intent`。
- `/schedule`、`/cancel`、扫描、投递与 `/ack` 均保持幂等。
- 计划改期产生新的 occurrence/job 标识，旧标识被取消或在客户端校验时拒绝。
- 周期计划每次只写入下一期，控制 Cloudflare KV 写入量。
- 现有 KV 日配额错误正文继续透传到客户端诊断，不退化为无信息的 HTTP 400。

## 去重与容量限制

- 每个角色最多 50 个 `active`、`paused`、`running` 或可重试 `failed` 计划。
- 同一角色、相同类型、语义相同目的且时间接近的创建操作应合并或更新。
- 周期计划按规范化重复规则参与去重。
- 历史记录不占有效计划上限，可由用户物理删除。
- 自动清理任务功能应扩展为可选择是否同时清除角色计划；默认不能在未明确说明时删除长期角色计划。

## 诊断与隐私

计划诊断记录阶段、时间、短计划 ID、短期次 ID、类型、错误码和脱敏摘要。不得记录 API Key、Authorization、完整提示词、完整私聊正文或完整计划依据。

安排表展示与单条计划相关的诊断；全局诊断页继续提供原生执行链阶段。诊断记录应有本地数量上限，避免长期计划产生无限日志。

## 测试与验收

必须覆盖：

- 明确承诺和角色私下决定的创建。
- 一次性、每天、每周、每月、固定间隔与结束条件。
- 模糊时间推定及后续精确时间更新。
- 继续聊天不取消明确承诺。
- “不想上班”不取消，“不上班了”和“辞职了”按范围取消。
- 角色日程开始、结束、取消及提示词过滤。
- 同一计划和期次的 FCM 重复投递只执行一次。
- 玩家手动待回复优先于计划和普通主动任务。
- 应用前台、后台、锁屏、进程回收、重启和离线恢复。
- 私聊、朋友圈生成成功后的本地持久化、UI 应用和云端确认。
- 周期计划只在结果持久化后推进下一期。
- API 403、余额不足、临时网络失败和 KV 写入额度错误。
- 计划改期/暂停/取消后旧推送被拒绝。
- 每角色 50 条上限、语义去重和历史不占上限。
- 设备时区变化、跨日、月末和夏令时边界。
- 隐藏标签不泄漏到聊天正文，诊断不泄漏敏感信息。
- 保留现有普通主动消息、朋友圈骰子、云端单任务、KV 清理和 Android 原生执行恢复测试。

## 发布要求

- 覆盖安装保留聊天、记忆、API 设置、设备绑定、现有 Room 任务和云闹钟配置。
- Room 数据库变更必须提供迁移，不允许破坏式重建。
- 新版本通过现有软件内更新通道发布。
- 发布前通过 npm 全量测试、Android JVM 测试、Lint、签名校验和线上更新清单验证。
