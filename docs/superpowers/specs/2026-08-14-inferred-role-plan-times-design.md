# 虞栖模糊时间自主安排设计

## 目标

虞栖可以把“明早”“待会”“今晚”“过几天”等自然、模糊的时间表达自主落成一个可执行的具体时间。用户不需要像设置机械闹钟一样提供精确时分，虞栖也不得因为时间是自己推测的就放弃安排或吞掉正常聊天回复。

## 核心语义

- `timeConfidence: explicit` 表示用户明确给出了足以确定具体执行时间的信息。
- `timeConfidence: inferred` 表示用户给出了自然时间范围或期待，由虞栖选择范围内的具体执行时刻。
- 两种时间置信度都可以形成真实的角色安排、云闹钟和后续主动行为。
- 推测出的具体时刻属于内部执行细节。虞栖在自然回复中不主动汇报该时刻；用户明确追问“几点”时，才可以根据当前安排回答。
- 用户明确给出具体时间时，继续使用代码拥有的精确确认文本，避免模型口头承诺与实际安排不一致。

## 直接聊天流程

1. 认知管线输出自然回复和闭合的 `rolePlanOperations`。
2. PC 运行时验证操作来源、类型、时间结构、角色归属、目标版本和计划容量。
3. 对合法的推测时间操作：
   - 保留在 canonical action set 中；
   - 参与确定性指纹和原子提交；
   - 由 Android 安排表与云闹钟照常执行；
   - 不触发精确时间确认渲染，保留模型的自然回复。
4. 对明确时间或取消、暂停、恢复、完成等需要公开确认的操作：
   - 继续使用代码拥有的确认渲染；
   - 确认文本只覆盖需要公开确认的操作。
5. 同一轮同时包含明确时间和推测时间时，两类动作都提交，但可见确认只列出明确部分；推测部分静默执行。

## 安全边界

- `inferred` 不是绕过 action authority 的开关。时间仍必须可解析、位于有效范围、指向当前角色并通过 canonical target resolution。
- 未知字段、未知操作、伪造目标版本、跨角色目标和无效时间继续拒绝。
- 私人决定沿用现有权限边界，不因本设计被冒充为用户要求。
- 明确时间的代码确认行为保持不变。
- 旧 protocol v1/v2、authority-v0 恢复以及已经提交的历史安排保持字节兼容。

## 错误处理

- 合法 `inferred` 操作不得再触发 `explicit time confidence is required`。
- 一个可执行安排不得因为“时间由虞栖推测”而被静默删除。
- 运行时仍不得为了保住动作而降低 canonical 校验、伪造时间或修改已经终态失败的历史 turn。

## 测试

- `requiresUserConfirmation` 对纯推测时间返回 `false`，但仍完整验证操作和时间结构。
- 明确时间继续返回 `true` 并生成精确确认。
- 真实 `runCanonicalReleaseTurn` 用例证明“明天还能收到早安吗”保留自然回复，同时提交一个 `timeConfidence: inferred` 的 `role_plan_create` action。
- 混合明确/推测操作同时提交，但确认文本只包含明确操作。
- 无效推测时间、未知字段、跨角色目标继续 fail closed。
- 相关 orchestrator、canonical commit、release executor 和 dispatcher 回归全部通过。

## 不在本次范围

- 不新增新的模糊时间解析器；具体时刻仍由认知模型根据上下文生成。
- 不改变主动聊天是否应该发生的动机判断。
- 不修改历史终态失败记录，也不伪造已经遗漏的回复。
