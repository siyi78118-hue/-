# 聊天引用与用户动态删除设计

**日期：** 2026-07-20  
**状态：** 已确认设计，待实施

## 目标

为虞栖专属 AL 增加两项完整联动能力：

1. 用户可以在私聊中引用虞栖此前的一条消息，并让界面、桥接小 g、聊天上下文和记忆整理都准确理解引用对象与说话人。
2. 用户可以删除自己发布的朋友圈动态，同时正确停止尚未发生的通知，并保留虞栖已经真实经历过的见闻和互动记忆。

## 范围

### 包含

- 长按虞栖消息后选择“引用”。
- 输入区展示可取消的引用预览。
- 发送后的用户消息展示引用卡片。
- 引用元数据随聊天持久化、Android 原生执行快照、电脑桥接请求、模型上下文和记忆整理传递。
- 用户自己的真实朋友圈动态提供删除入口和确认流程。
- 删除动态后同步更新本地朋友圈、应用状态镜像和仍在运行的通知任务。
- 已看过动态的虞栖保留此前见闻；未看过的虞栖不会因删除操作获得动态内容。

### 不包含

- 引用用户自己的消息。
- 引用系统提示、撤回消息、已删除消息或正在生成的临时气泡。
- 动态回收站、恢复、批量删除或删除虞栖发布的动态。
- 删除已经由记忆系统形成、且代表虞栖真实经历的见闻。

## 方案选择

采用完整联动方案：引用与删除均作为真实数据行为实现，而不是只改变当前页面的显示。

未采用纯前端方案，因为它会导致小 g 看不到引用关系、删除后的动态仍可能触发后台互动。未采用永久软删除审计方案，因为当前产品不需要恢复入口，保留完整墓碑会增加本地、桥接与云同步的状态复杂度。

## 聊天引用设计

### 交互

- 长按虞栖的普通文字、语音、红包或转账消息，现有消息菜单在“删除”之外增加“引用”。
- 点击“引用”后关闭长按菜单，在聊天输入框上方显示引用预览：说话人名称、可读文本摘要以及关闭按钮。
- 引用预览不会自动填入输入框；用户可以继续输入文字，点击关闭按钮可取消引用。
- 发送成功后清空当前引用选择。
- 用户消息气泡内展示紧凑引用卡片，卡片位于用户本次正文上方。
- 引用卡片使用发送时保存的快照。源消息日后被删除时，已经发出的引用仍可读。

### 数据结构

用户发送的消息增加可选字段：

```json
{
  "quote": {
    "messageId": "msg_source",
    "speakerId": "yuqi",
    "speakerType": "assistant",
    "speakerName": "虞栖",
    "contentType": "text",
    "content": "发送时的原文或可读摘要"
  }
}
```

约束：

- `speakerType` 固定为 `assistant`，`speakerId` 固定为当前角色 ID，不能由显示文字反推。
- `speakerName` 和 `content` 是发送时快照；角色改名或源消息删除后不回写旧引用。
- 普通文字保存原文；语音优先保存转写，缺少转写时保存“[语音]”；红包与转账保存类型、金额与备注的可读摘要。
- 发送前再次校验源消息属于当前会话、角色为虞栖且未撤回或删除；校验失败时取消引用并提示用户重新选择。

### 上下文和记忆

- UI 显示使用 `quote` 快照，不把引用原文拼进用户正文。
- 发送给聊天小 g、记忆小 g 和兜底聊天 AI 时，以结构化、明确归属的文本表示：用户本次说了什么，以及用户引用了哪位角色的哪句话。
- 上下文序列化必须显式包含 `speakerType=assistant`、角色 ID 和角色名，禁止仅凭“虞栖说”之类自然语言推断归属。
- 引用原文只作为本次用户表达的上下文，不产生一条新的虞栖发言，避免重复计入聊天和记忆。
- 本地聊天、Android 快照、桥接输入及备份导出保留同一份 `quote` 对象。

## 删除用户动态设计

### 交互

- 用户自己的真实动态右侧 `··` 打开动作菜单，提供“通知角色”和红色“删除动态”。
- 虚拟占位动态、虞栖动态及其他角色动态不显示删除入口。
- 点击删除后显示一次确认，说明删除后朋友圈不再显示，但已经看过的人仍可能记得。
- 确认后立即从朋友圈列表移除并提示“动态已删除”。

### 删除流程

删除函数以动态 ID 为唯一输入，并按下列顺序执行：

1. 校验动态存在且 `authorType === "player"`，拒绝删除其他来源动态。
2. 记录该动态已看过或互动过的角色集合，用于保护他们已经形成的经历。
3. 从 `allMoments` 移除动态并立刻持久化，确保所有异步回调重新查找时得到“不存在”。
4. 取消或忽略当前动态的本地通知飞行；后续 AI 点赞或评论结果在写入前必须再次检查动态仍存在。
5. 更新应用状态镜像，使电脑端、小 g 备份和后续主动任务不再看到该动态。
6. 对仍未看过该动态的角色，不写入动态正文、删除事件或任何新记忆。
7. 对已经看过、点赞或评论过的角色，保留此前已经记录的见闻和互动；不把删除解释为遗忘。

### 竞态与失败处理

- 若删除发生在朋友圈通知 AI 请求期间，请求可以自然结束，但结果不得写回已删除动态，也不得新增“看过、点赞、评论”记忆。
- 若持久化成功而状态镜像暂时失败，本地删除仍然成立；镜像按现有恢复机制在后续同步时重试。
- 重复删除同一动态返回无变化，不报致命错误，也不重复生成记忆。
- 删除不触发聊天 AI 或记忆 AI 调用，因此不会额外消耗模型额度。

## 组件边界

- **聊天引用选择器：** 维护当前会话尚未发送的引用目标，负责选择、取消和发送后清空。
- **引用快照构造器：** 从可引用消息生成稳定、带说话人归属的 `quote` 数据。
- **引用渲染器：** 渲染输入区预览和消息气泡中的引用卡片。
- **引用上下文序列化器：** 将结构化引用转成小 g 与记忆 AI 可理解但不会混淆归属的上下文。
- **用户动态删除器：** 校验作者、先移除数据、再处理飞行任务和镜像同步。
- **动态通知提交守卫：** 所有异步互动结果落盘前重新确认动态仍存在。

## 测试策略

### 引用

- 只有可见且未撤回的虞栖消息能生成引用快照。
- 文字、语音、红包和转账生成正确摘要及明确说话人字段。
- 选择、取消和成功发送引用时，输入区状态正确变化。
- 发送后的引用卡片在源消息删除后仍显示快照。
- 普通通道、Android 原生通道和重试通道保留同一引用元数据。
- 小 g 与记忆上下文明确把引用内容归属于虞栖，不会挂到用户头上，也不会重复成一条新消息。

### 动态删除

- 只能删除 `authorType=player` 的真实动态。
- 删除立即更新本地存储和页面，重复删除安全无副作用。
- 删除前已看过的角色原有记忆保留。
- 删除前未看过的角色不会生成任何动态或删除记忆。
- 删除发生在通知请求期间时，迟到的点赞、评论和见闻不会落盘。
- 状态镜像失败不恢复已删除动态，后续同步仍以删除后的列表为准。

### 回归

- 现有撤回、删除消息、红包、转账、语音、批量发送、失败重试、主动私聊和朋友圈回复仍通过。
- Android 单元测试、基础 Node 测试和正式签名 APK 构建全部通过。

## 验收标准

1. 用户可在手机端长按虞栖消息完成引用、取消引用和发送引用。
2. 虞栖的回复能够正确理解用户引用的具体原话和说话人。
3. 引用不会造成“虞栖说的话记到用户头上”的错误。
4. 用户可删除自己发布的动态，删除后界面、本地数据、镜像及未来通知均不再包含该动态。
5. 已经看过该动态的虞栖仍保留真实经历；未看过的虞栖不会凭空知道。
6. 删除期间的迟到异步结果不会让动态或互动死灰复燃。
7. 新 APK 使用项目原签名，可直接覆盖现有安装并保留数据。
