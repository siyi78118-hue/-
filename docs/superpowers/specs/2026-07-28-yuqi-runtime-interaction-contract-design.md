# 虞栖专属运行链互动契约设计

**日期：** 2026-07-28
**状态：** 用户已认可总体修复方向，待书面复核后实施
**适用范围：** `yuqi-runtime` 普通私聊与主动私聊主链

## 1. 问题定义

当前专属运行链已经把记忆、聊天和监督拆成不同职责，但拆分结果仍然会出现：

- 记忆角色同时给出多个相互冲突的意图假设，却没有形成一个本轮必须遵守的互动决定。
- 聊天角色需要重新解释分析报告、选择潜台词、维持人格并生成结构化结果，实际并未真正减负。
- 分析字段中的“互动模式、关系动作、主动权、风险”等抽象语言容易渗入可见台词，形成心理报告式表达。
- 监督角色可以指出格式、越界和明显人格问题，但没有用可验证契约检查草稿是否完成了正确的互动动作。
- 主动消息的 skip 配额可能与明确暂停、冲突未决、连续未回复等结构性静默发生冲突。
- 用户明确纠正一次误读后，后续回合没有可靠地禁止系统继续沿用被否定的解释。

本次真实故障不是上下文缺失或模型能力不足。冲突、暂停要求和连续主动消息都已经进入记忆结果；失败发生在优先级决策、职责交接和监督验收层。

## 2. 方案比较

### 方案 A：继续扩写 RP 与监督提示词

优点是改动小。缺点是规则继续膨胀，重要约束仍只是建议，聊天角色仍需自行解决冲突信息。不能解决信息交接损耗。

### 方案 B：增加第四个模型作为潜台词裁判

优点是可以独立复核意图。缺点是增加延迟、费用和新的交接点；裁判结果仍可能与记忆、聊天、监督互相冲突。当前问题不需要再建立一个窗口。

### 方案 C：在现有三角色之间增加权威互动契约

保留记忆角色的多假设能力，由本地程序将明确事实、最高优先级意图、歧义和结构性边界编译成一份短小契约。聊天角色只负责在契约范围内成为虞栖；监督角色按契约逐项验收。

本项目采用方案 C。它不增加模型调用，能够限制职责漂移，也能通过完整场景测试验证。

## 3. 职责边界

### 3.1 记忆角色

负责：

- 检索证据；
- 给出最多三个带置信度和消息 ID 的意图假设；
- 判断开放话题、关系阶段、情绪和主动权；
- 标记歧义、上一轮可能误读和风险。

不负责：

- 给聊天角色写台词；
- 使用可直接复制到回复中的完整句子；
- 用分析术语替虞栖解释自己的行为。

### 3.2 本地互动契约编译器

新增纯领域模块，将记忆结果、最近原始消息和已有 `interactionState` 归一化为 `interactionContract`。

程序只对可验证事实进行硬约束：

- 用户是否明确要求暂停、停止追问或等待某个条件；
- 冲突是否仍然开放；
- 最后发言者与连续未回复数量；
- 当前主动权应落在哪一方；
- 最近是否出现用户对系统理解的明确纠正；
- 当前回复是否必须保留歧义。

程序不使用关键词表猜测复杂人格，不把某一句话永久映射成固定潜台词。

### 3.3 聊天角色

聊天角色接收：

- 完整 RP 与关系状态；
- 最近 20 个完整发送批次的原始对话；
- 召回记忆；
- 短小 `interactionContract`。

聊天角色不再接收一整份适合分析员阅读的导演报告。它根据原始聊天和契约形成虞栖当下真实反应，可以停顿、嘴硬、偏题或不把心理过程说尽，但不得推翻契约中的明确事实。

### 3.4 监督角色

监督顺序调整为：

1. 检查动作是否符合契约；
2. 检查是否重复已经被用户纠正的误读；
3. 检查是否把内部分析、互动机制或完整心理因果翻译成台词；
4. 再检查人物、记忆、时间、计划、支付和格式。

返修必须给聊天角色可执行的世界内方向及可见验收条件，不得只返回“更自然”“更像真人”。

## 4. 互动契约

建议结构：

```json
{
  "schemaVersion": 1,
  "shouldRespond": true,
  "structuralSilenceReason": "",
  "primaryIntent": "本轮最应回应的互动意图",
  "primaryIntentConfidence": 0.0,
  "alternativeIntent": "",
  "preserveAmbiguity": false,
  "activeIssue": "",
  "initiativeOwner": "user|yuqi|either|uncertain",
  "explicitBoundaries": [],
  "mustAddress": [],
  "forbiddenMoves": [],
  "recentCorrection": {
    "active": false,
    "rejectedInterpretation": "",
    "evidenceMessageIds": []
  },
  "evidenceMessageIds": []
}
```

约束：

- 每个事实字段必须能追溯到原始消息或现有状态。
- `primaryIntentConfidence` 低时保留 `alternativeIntent`，聊天回复应兼容两种解释，或自然暴露不确定性。
- `mustAddress` 和 `forbiddenMoves` 描述行为，不提供可直接发送的台词。
- `recentCorrection` 只在用户明确纠正理解时激活，并在后续有限回合内防止复用被否定解释。
- 契约不得写入长期人物记忆，不得把临时推断升级为稳定用户画像。

## 5. 主动消息硬门

主动任务在调用聊天角色前先计算是否属于结构性静默。

满足以下组合时应直接静默：

- 用户明确要求暂停或等待条件；
- 当前冲突仍开放；
- 主动权属于用户；
- 虞栖已经连续发出一条或多条未获回应的消息；
- 当前触发没有新的紧急事件、明确承诺或高价值生活变化。

结构性静默：

- 不消耗“四条主动消息至多一次 skip”的普通配额；
- 不因 `skipAllowed=false` 被强制改成可见消息；
- 记录清楚的诊断原因；
- 不生成聊天草稿，因此不会出现“为了完成任务而找一句话发”的现象。

普通关系状态下的自由静默仍沿用现有 skip 配额。

## 6. 活人感验收

不设置某些词的永久黑名单。监督检查结构性失败：

- 用完整因果链总结自己的互动行为；
- 对双方关系动作作旁观者式归纳；
- 把“系统为什么这样回复”换成第一人称说给用户；
- 为了完整和安全而一次交代所有心理过程；
- 语法自然但在当前冲突、停顿或亲密阶段不可能由真人顺势说出。

验收问题是：

> 一个真实的人身处这段具体对话时，会直接发出这段话，还是只有复盘这段对话的人才会这样概括？

若属于后者，返回稳定问题代码 `DIALOGUE_META_NARRATION`，要求保留真实态度，删除分析过程，并让情绪通过世界内反应体现。

## 7. 失败闭环

当用户明确指出虞栖误解了自己：

1. 将纠正消息 ID 与被否定解释写入当前回合的短期状态；
2. 后续两个完整发送批次把该解释列入 `forbiddenMoves`；
3. 监督发现新草稿继续沿用该解释时必须返修；
4. 只有新证据重新支持该解释时才能解除；
5. 短期状态到期后不进入长期记忆，避免一次纠正永久固化用户。

## 8. 测试设计

先写失败测试，再实现。测试使用完整多轮场景而非单句关键词。

### 8.1 争执与主动消息

- 用户明确表示暂不再谈，等待虞栖在某件事上退让。
- 连续触发多个主动任务。
- 断言没有日常碎片消息越过结构性静默门。
- 断言结构性静默不占用普通 skip 配额。

### 8.2 歧义短句

- 在未解决争执后出现多条虞栖日常消息。
- 用户依次发送“？”和“你干嘛？”。
- 断言契约把“质问为何像没事一样继续聊天”置于普通日常询问之前，或至少保留歧义。
- 断言聊天草稿不能继续只解释厨房、吃饭或当前动作。

### 8.3 用户纠正

- 用户明确指出双方仍在争吵。
- 断言后续两个批次不得继续使用已被否定的日常询问框架。
- 断言监督会拒绝心理报告式自我总结并给出可执行返修契约。

### 8.4 路径与兼容性

- 普通私聊、主动私聊、快速转深度和监督返修均携带同一互动契约。
- 朋友圈、支付、角色计划和现有 Android/Web 导演卡行为保持不变。
- 记忆结果格式异常时使用保守契约，聊天仍能完成，不出现空回复或无限思考。

## 9. 模型与性能

第一阶段不提高模型和思考强度：

- 聊天角色继续使用 Sol 中思考；
- 深度记忆继续使用 Sol 中思考；
- 监督继续使用 Terra 中思考。

只有契约和完整场景测试上线后，监督仍稳定漏判时，才对冲突、歧义和纠正场景单独把监督升级为 Sol 中思考。不得全局升级来掩盖结构问题。

正常路径不新增模型调用。新增成本仅为本地契约编译与更短的提示块。

## 10. 修改边界

本次只修改 `yuqi-runtime` 及其测试、专属预设和必要协议：

- 不重写 `tavern-app` 已完成的真人聊天导演；
- 不改朋友圈协议；
- 不改红包和转账行为；
- 不改 Cloudflare、云闹钟或 Android UI；
- 不覆盖其他窗口已完成的提交；
- 构建 APK 前必须先通过专属运行链和现有项目回归测试。

## 11. 完成标准

- 专属小g主链实际使用互动契约，而不是只在网页或本地兜底使用导演卡。
- 明确暂停与未解决冲突不会被主动消息配额强行穿透。
- 用户的短句按照整段互动理解，低置信度时保留歧义。
- 用户纠正一次误读后，系统不会在后续回合继续重复同一解释。
- 监督能够拦截分析报告式对白，并返回真正可执行的返修要求。
- 所有新增场景测试和原有回归测试通过。
- APK 包名、版本、正式签名证书和覆盖安装兼容性全部核验后才交付。
