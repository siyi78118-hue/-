# 虞栖消息重试与模型故障转移设计

## 目标

彻底解决聊天长期停留在“正在认真想”、失败后“重新发送”无效、旧结果迟到造成重复回复的问题。

验收标准：

1. 模型临时满载时，本轮自动切换备用模型继续，不要求用户重新发送。
2. 额度耗尽、网络中断或最终失败后，用户点击“重新发送”会创建新的执行任务。
3. 新任务仍绑定原来的用户消息气泡，不复制用户消息。
4. 同一条用户消息最多显示一组最终回复；旧任务迟到时不会覆盖或追加第二组回复。
5. 应用重启、电脑服务重启、云信箱重复投递和连续点击均保持上述约束。

## 标识分层

系统不再把“聊天气泡”和“执行任务”共用同一个标识：

- `sourceMessageId`：原聊天气泡的稳定标识，重试时保持不变。
- `turnId`：一次执行任务的唯一标识，每次人工重新发送生成新的值。
- `attemptId`：Android 本地执行任务内部的尝试标识，由原生执行层管理。
- `retryOfTurnId`：新任务指向前一失败任务，仅用于诊断和追踪。

回复最终仍通过 `sourceMessageId` 绑定原聊天气泡；网络、数据库和小g线程通过新的 `turnId` 区分不同执行。

## 数据流

### 首次发送

1. 前端创建用户消息气泡和稳定 `sourceMessageId`。
2. 前端创建首次 `turnId`，提交 Android 原生执行层。
3. Android 将任务通过局域网或云信箱送到电脑。
4. 电脑端按 `turnId` 幂等执行并返回结果。
5. Android 以 `sourceMessageId` 将回复落到原气泡之后。

### 人工重新发送

1. 仅当原消息没有任何成功回复且当前没有运行中的任务时，按钮可用。
2. 前端生成全新的 `turnId` 和新的 `deviceSeq`，保留原 `sourceMessageId`、正文、引用、支付上下文及批次上下文，并立即把新 `turnId` 设为该气泡的 `activeTurnId`。
3. 新任务在 `context.retry` 中携带 `retryOfTurnId` 和 `canonicalMessageId`，通过 `submitTurn` 创建，而不是对旧任务调用 `retryTurn`。
4. 电脑端验证旧任务属于同一设备、同一角色和同一原消息，且新消息内容与已存规范消息一致后，复用已存的规范用户消息，不重复写入记忆。
5. 新任务独立执行；旧任务继续保留为失败诊断。

## 模型故障转移

每个小g阶段允许一次同角色备用模型切换：

- 记忆：首选由现有快/深通道路由决定；首选模型满载时切到另一可用模型。
- 聊天：首选 `sol`；`sol` 满载时切到 `terra`。
- 监督：首选 `terra`；`terra` 满载时切到 `sol`。

只有明确的容量类错误触发模型切换，例如 `Selected model is at capacity`。额度耗尽不会盲目切换模型，因为它通常属于账号级限制；此时快速返回可兜底的终态失败。

每次故障转移写入诊断，包含阶段、首选模型、备用模型和错误类别，不记录密钥或完整提示词。

## 唯一回复裁决

Android 以 `sourceMessageId + activeTurnId` 裁决唯一可见回复：

- 首次发送时，首次任务就是 `activeTurnId`；用户点击重新发送后，新任务立即取代旧任务成为 `activeTurnId`。
- 只有当前 `activeTurnId` 的成功结果可以渲染；被人工重试取代的旧任务即使迟到，也只确认收件，不再渲染。
- 当前权威任务成功落库后，该 `sourceMessageId` 进入完成态，后续任何任务均不得追加第二组回复。
- 支付状态、关系阶段动作和日程动作只允许权威任务应用一次。
- 失败任务不能覆盖已经成功的回复。

## 状态与错误处理

- `pending/running`：隐藏“重新发送”，防止并发点击。
- `completed`：清除失败状态，不再显示重试按钮。
- `failed`：显示失败原因和“重新发送”。
- 云端只收到旧失败结果：更新旧任务诊断，不改变当前新任务的界面状态。
- 新任务提交失败：恢复为可重试状态，保留新的失败原因。
- 应用重启：从本地数据库恢复当前权威任务，不依赖内存变量。

## 兼容性

- 已安装版本产生的旧失败任务仍可显示和重新发送。
- 新版本首次重试旧任务时生成新的 `turnId`。
- 现有聊天内容、记忆、引用、红包和转账上下文不迁移、不删除。
- 不修改正式签名身份，APK 可以覆盖安装。

## 测试

至少覆盖：

1. 首次失败后重试产生不同 `turnId`、相同 `sourceMessageId`。
2. 服务端接受规范消息复用，不新增第二条用户记忆。
3. `sol` 容量错误自动切换 `terra` 并完成。
4. 额度耗尽不进行无效模型轮换。
5. 人工重试后旧任务先于新任务迟到，也不产生回复；只有新的 `activeTurnId` 可以落屏。
6. 重复点击只创建一个运行任务。
7. 应用重启后仍能恢复当前重试任务。
8. 引用、红包、转账和批次上下文在重试中完整保留。
