# 虞栖阶段与场景连续性补全设计

## 1. 背景与根因

虞栖专属运行时接管聊天后，手机仍保留五阶段编辑、切换、回滚和旧记忆 AI 阶段复核代码，但新的 Android 桥接没有把普通聊天快照中的动态关系数据送进电脑运行时。电脑端的记忆、聊天和监督请求又固定使用 `initial`。因此关系阶段只剩界面外壳，既不稳定影响生成，也不能由新记忆链路推进。

同一次迁移还留下四类断点：私有安排任务类型没有被自动任务判定器识别；监督仍使用二态协议；互动状态只实现时间和基础未回复计数；朋友圈点赞、评论与评论回复仍绕过聊天小 G，直接调用手机旧聊天接口。

## 2. 目标

1. 恢复五阶段：`new` 初识、`acquainted` 认识、`familiar` 熟悉、`close` 亲近、`committed` 关系确立。
2. 手机每轮传递当前阶段、阶段正文、双方昵称、会话补充和稳定场景资料；电脑运行时不再硬编码初识。
3. 记忆小 G每轮可提出阶段复核，AL 按确定性门槛验证；同轮聊天小 G与监督使用验证后的有效阶段，手机收到后幂等回写并保留撤销历史。
4. 修正所有自动任务种类，私有安排也能正常 `skip`，不得重新产生“等你有空再聊”兜底。
5. 监督升级为 `approve|rewrite|skip|reject` 四态，自动任务可立即静默，被动任务拒绝时进入可恢复失败。
6. 互动状态补齐阶段、最近双方正文、主动联系轮数、上一自动结果和时间阈值。
7. 朋友圈点赞、评论和评论回复交由现有聊天小 G兼职，不新增模型角色或窗口。
8. 构建并交付使用原正式证书签名、可覆盖现有正式版的 APK。

## 3. 非目标

- 本批不实现手机与电脑结构化事实库的完整双向合并；原始消息同步与现有两端记忆流程保持。
- 不新增“朋友圈小 G”或第四个运行会话。
- 不重写五个阶段的用户可编辑正文。
- 不让云端定时器生成角色文案。

## 4. 动态场景契约

手机生成独立于固定 RP 的 `scene` 对象：

```json
{
  "playerName": "玩家昵称",
  "characterName": "虞栖",
  "relationshipStage": {
    "id": "familiar",
    "label": "熟悉",
    "content": "当前阶段用户编辑正文",
    "since": 1780000000000,
    "reason": "阶段形成原因",
    "confidence": 0.9
  },
  "conversationExtraPrompt": "当前会话补充",
  "globalExtraPrompt": "全局补充",
  "stageCatalog": [
    {"id":"new","label":"初识"},
    {"id":"acquainted","label":"认识"},
    {"id":"familiar","label":"熟悉"},
    {"id":"close","label":"亲近"},
    {"id":"committed","label":"关系确立"}
  ]
}
```

固定的 AL 综合 RP 与 `yuqi-core` 继续由电脑版本化预设提供。动态场景只能追加，不能替换固定预设。普通聊天把 `scene` 放入直接事件 `context`；自动任务放入触发器 `context.scene`。协议只接受白名单字段和有限长度文本。

## 5. 阶段复核与回写

记忆小 G输出增加 `relationshipStageReview`：当前阶段、建议阶段、置信度、理由、证据消息 ID、是否为双方明确确认。AL 仅在下列条件全部满足时接受变化：

- 建议阶段存在于手机传来的阶段目录；
- 置信度至少 `0.82`；
- 普通变化至少两个有效证据消息，明确双方确认至少一个；
- 非明确双方确认最多移动一个相邻阶段；
- 理由非空，证据消息确实存在于权威原始消息库。

接受后，本轮聊天与监督立即使用新阶段；提交结果携带 `relationshipStageAction`。Android 将其转换为 `RELATIONSHIP_STAGE` 回复部件，手机按 turnId 幂等更新 `currentStage`、`state` 和 `history`。手动切换始终是下一轮输入的权威当前阶段，撤销功能继续有效。

## 6. 监督与自动任务

监督结果改为：

```json
{"decision":"approve|rewrite|skip|reject","issues":[]}
```

- `approve`：提交草稿。
- `rewrite`：最多交回聊天小 G重写两次。
- `skip`：自动任务成功静默；被动回复不得静默，转为可恢复失败。
- `reject`：终止，不产生可见内容。

自动任务集合统一包含公开/私有角色安排、主动私聊、主动朋友圈、朋友圈互动和评论回复。任何自动场景的空输出都不得修复成聊天套话。

## 7. 互动状态

每轮执行时从电脑权威消息库重建：真实执行时间、触发事件时间、处理延迟、最近双方消息 ID/正文/时间、沉默时长、未回复气泡数、用户最后回复后的自动联系轮数、上一自动任务结果、是否跨天以及 15 分钟、60 分钟、6 小时、24 小时阈值、当前有效关系阶段。手机旧快照中的动态计数只作参考，不得覆盖运行时计算值。

## 8. 朋友圈结构化任务

不新增模型窗口。现有聊天小 G根据场景兼职处理：

- `MOMENT_INTERACTION`：玩家发布朋友圈后，决定跳过、只点赞、只评论或点赞并评论。
- `MOMENT_REPLY`：玩家评论虞栖动态或回复虞栖评论后，决定回复或静默。
- 现有 `PROACTIVE_MOMENT` 与角色安排朋友圈继续生成朋友圈正文。

聊天小 G结构化输出增加可空的：

```json
{"momentAction":{"momentId":"mom_x","like":true,"comment":"评论正文","replyToCommentId":""}}
```

朋友圈任务不创建私聊消息。运行时提交动作结果，Android 转成 `MOMENT_ACTION` 回复部件，手机使用动态 ID、角色 ID、来源评论 ID和 turnId 去重后落库。只有手机确认落库后才进入现有朋友圈记忆记录。`skip` 标记任务成功完成，但不产生点赞、评论、通知或私聊气泡。

虞栖的朋友圈任务不再直接调用手机旧聊天 API；桥接不可用时保留可重试失败，不偷偷生成另一套人格内容。

## 9. 错误处理与兼容

- 缺失或非法动态场景时，以 `new` 初识安全默认，但写诊断；不得使用任意文本覆盖固定 RP。
- 旧客户端没有 `scene` 时继续可聊天，但不会自动推进阶段，并在诊断标记 `scene_missing`。
- 阶段动作或朋友圈动作重复到达时必须幂等。
- 朋友圈动作落库失败时不确认 UI 应用，保留原生收件箱重试。
- 正式签名、包名 `com.siyi.al` 和现有 Room 数据不变。

## 10. 验收

- 普通、主动、支付、公开/私有安排均能证明当前阶段传给记忆、聊天和监督。
- 通过符合门槛的证据可从 `new` 推进到 `acquainted`，低置信度、单方面称呼或无效证据不能推进。
- 私有安排返回 `skip` 时没有可见消息，也不出现“等你有空再聊”。
- 监督可以立即 `skip` 自动任务、`reject` 风险任务；不存在第三次强制放行。
- 玩家朋友圈可得到零动作、点赞、评论或二者；玩家评论可得到回复或静默，全部由聊天小 G生成并经监督。
- 全量 Node、运行时、Android JVM 和预设同步测试通过；正式 APK 证书与现有正式版 SHA-256 指纹一致。
