# 虞栖纯文本空附件兼容修复设计

## 问题

手机图片消息功能在 `1f0e199` 中让所有直接回复任务都持有 `attachments: []`。封包时空数组是 truthy，因而纯文本消息也把空附件字段发给后台。协议层只允许附件字段缺省，或恰好包含一张图片，于是纯文本消息在入队前持续失败：

`direct message supports exactly one image attachment`

## 已确认实例

- 用户消息：`现实很残酷的 小傻子天真小姐姐`
- turn：`turn_msg_1785130887070_71kpb0`
- relay：`relay_0874a46b06f3137fe488396b`
- 云端仍未确认，约每 60 秒重试一次。
- memory、brain、supervisor 均未启动。

## 方案

采用双层兼容：

1. 手机封包层仅在附件数量为 1 时写入 `message.attachments`；纯文本消息完全省略该字段。
2. 后台协议层将历史或旧客户端发送的 `attachments: []` 规范化为字段缺省；非空附件仍必须恰好为一张合法图片，多张或伪造附件继续拒绝。

该方案同时修复新消息和已经滞留在云中继中的消息。只改附件规范化，不放宽图片大小、格式、签名、数量等安全约束。

## 验收

- 协议测试证明 `attachments: []` 被接受并从规范化消息中删除。
- 协议测试继续证明多张图片被拒绝。
- UI 合约证明纯文本封包使用条件展开，不产生空附件字段。
- 图片消息仍携带一张附件。
- 全量测试通过。
- 重启后台后，滞留 turn 被自动接收、提交并从云中继确认。
