# 云闹钟状态摘要设计

## 目标

设置页的“状态”只回答用户当前最关心的四件事：功能是否可用、下一次主动私聊、下一次主动朋友圈、当前是否存在同步异常。用户不需要从任务代数、内部 ID、历史错误和接口原文中寻找结论。

## 默认摘要

- 最多四行。
- 第一行显示 `运行状态`，区分未开启、未绑定、运行正常、正在同步和当前同步异常。
- 第二、三行分别显示最近一项有效的私聊与朋友圈计划，格式为角色名加本地时间；没有计划时显示“尚未安排”。
- 第四行仅在当前有效计划仍处于同步中或同步失败时出现。`synced` 不另占一行。
- 摘要不显示任务代数、epoch、jobId、变更来源、仅内存检查时间、旧失败、Worker 版本、接口检测、模型调用或原始 HTML。
- 历史失败不能覆盖当前计划的健康状态。只有当前有效计划的 `cloudSyncState` 可以形成摘要异常。

## 详细诊断

- 不删除现有状态与错误证据。
- “诊断”页面新增“主动消息调度”区块，显示现有完整技术信息，包括任务代数、jobId、同步状态、变更来源、历史结果、链路、确认状态、Worker 与接口检查。
- 原始诊断文本在诊断页可换行显示；设置页永远不显示整段 HTML。
- 最近模型调用继续留在诊断页，不再附加到设置页摘要。

## 兼容边界

- 只改变 Web 展示和诊断分层，不写入或修改 Android Room、D1、Alarm、WorkManager、Service Worker 的调度权威。
- 原生 Android 与浏览器兼容模式都能生成摘要。
- 诊断页面没有模型调用记录时仍显示主动消息调度区块。

## 验收

- 构造包含 2026 年 7 月旧失败、HTML 错误、任务 ID 和当前有效计划的状态，设置页输出不超过四行且不含上述技术文本。
- 当前同步失败时显示一条简短异常；同步恢复后该异常消失。
- 诊断文本仍包含旧失败、任务 ID、链路与 Worker 信息。
- 设置页渲染不再读取最近模型调用，因此异步调用日志不能把旧内容重新写回摘要。
