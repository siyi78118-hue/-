# Android 原生执行链恢复设计

## 基线与目标

本修复以提交 `5f555dc`（`fix: prevent cloud timer KV task leaks`）和网页构建 `2026-07-16.86` 为基线。不得回退该提交的单任务调度、KV 任务清理、朋友圈独立骰子周期或云闹钟版本检查。

目标是修复 Android 1.0.58 中共同影响普通手动回复、主动私聊和朋友圈的原生执行链：任务可在前台、后台、锁屏、进程回收及应用重启后持续推进；同一任务只生成一次；真实失败必须在软件诊断中可见；前台主动任务不得替代尚未完成的手动回复。

## 已确认故障边界

1. WebView 已成功提交 `DIRECT_REPLY`，原生前台服务也收到新的启动请求。
2. 记忆 AI 请求成功，但聊天 AI 请求没有到达服务商。
3. 常驻原生服务随后处于空闲；强制停止并重启后才出现新的生成。
4. 当前 DAO 正常循环只领取 `QUEUED`；中间状态主要依赖服务创建时的一次 `recoverInterruptedWork()`。
5. FCM 入口只读取 `${charId}:${kind}` 最新快照，并严格比较 `cloudJobId`；新任务覆盖快照后，旧推送可被静默丢弃且不回执。
6. “前台私聊已生成”属于主动私聊补跑，不是手动回复完成证据。

## 设计

### 1. 可持续恢复的原生状态机

- 将可安全继续的 Turn 纳入普通领取循环：`QUEUED`、`MEMORY_DONE`、`CHAT_DONE`。
- `MEMORY_RUNNING` 在进程或执行器中断后允许重新执行记忆筛选；记忆结果不直接展示，不会造成重复聊天气泡。
- `CHAT_RUNNING` 若结果未知，保持 `INTERRUPTED`，不得自动重复调用聊天模型；由明确重试创建新 Attempt。
- 每次服务唤醒都执行恢复扫描，不再用服务生命周期内的一次性布尔值阻止后续恢复。
- 清空队列后再次检查可运行任务，关闭 `draining` 与新任务入队之间的丢失唤醒窗口。

### 2. 按云端任务保存原生快照

- 调度成功后同时保存稳定别名快照 `${charId}:${kind}` 和任务快照 `${charId}:${kind}:${jobId}`。
- FCM 优先按 `jobId` 读取任务快照；仅为兼容旧版本才回退稳定别名。
- 有 `jobId` 时不得用属于另一个任务的稳定别名快照执行。
- 快照缺失、任务 ID 不匹配、自动任务关闭都写入本地诊断；旧任务应被明确拒绝并停止无限重投，而不是静默返回。
- 自动任务批量清理继续只处理 `PROACTIVE_CHAT` 和 `PROACTIVE_MOMENT`，不得删除普通 `DIRECT_REPLY`。

### 3. 前台合并顺序与防冒充

- 应用启动或回到前台时，先读取并应用原生 Turn 状态，再恢复未完成手动回复，最后检查到期主动任务。
- 任一角色存在未完成的 `DIRECT_REPLY` 时，该角色的主动私聊不得前台补跑。
- 原生 Turn 完成后按 `turnId`、`sourceMessageId` 和 ReplyPart ID 幂等写入；主动消息不得绑定到玩家手动消息的 `replyToMessageId`。
- Android 继续以原生执行层作为生成权威路径；网页模型调用只作为非 Android 浏览器兼容路径，不在 Android 上与原生任务竞速。

### 4. 可见诊断

- Room 记录并由 Capacitor 插件只读暴露以下事件：`FCM_RECEIVED`、`SNAPSHOT_MISSING`、`JOB_MISMATCH`、`TURN_QUEUED`、`MEMORY_STARTED`、`MEMORY_DONE`、`CHAT_STARTED`、`CHAT_DONE`、`TURN_FAILED`、`ACK_OK`、`ACK_FAILED`。
- 诊断包含时间、Turn ID/Job ID 短标识、种类、阶段、错误码和脱敏错误摘要；不得包含 API Key、Authorization、完整系统提示词或完整私聊正文。
- 软件诊断页区分“手动原生回复”“后台主动私聊”“后台朋友圈”“前台兼容补跑”。

## 错误与重试规则

- 外部请求发出前的配置、URL、JSON 和本地存储错误可安全重试。
- 记忆请求失败按既有 RetryPolicy 分类；记忆成功后必须持久化 `MEMORY_DONE`，随后即使服务暂停也能继续聊天阶段。
- 聊天请求发出后结果未知时不得自动重复扣费；显示可重试错误，由用户触发新 Attempt。
- Worker 回执失败不影响已生成内容落地；后续服务唤醒继续回执，但不得重新生成正文。

## 回归验证

1. `MEMORY_DONE` Turn 无需重启即可被再次领取并进入聊天阶段。
2. `CHAT_DONE` Turn 无需重复模型调用即可提交 ReplyPart。
3. 清空队列边界插入的新任务不会丢失唤醒。
4. 服务同一生命周期内第二次唤醒仍会恢复中间状态。
5. 两个同角色同种类的不同 `jobId` 使用各自快照，旧推送不会读取新快照。
6. 快照缺失和 ID 不匹配产生可见诊断，不会静默循环。
7. 存在未完成手动回复时，前台主动私聊不会生成替代消息。
8. 保留 `5f555dc` 的云端单任务、KV 清理、朋友圈骰子与现有自动任务清理测试。

## 发布

- 在现有更新通道上递增 Android `versionCode` 和 `versionName`，不得降低或覆盖 1.0.6/当前已发布构建。
- 覆盖安装必须保留聊天、记忆、API 设置、设备绑定和现有 Room 数据。
- 发布清单、APK 下载地址和软件内检查更新结果必须指向同一个新构建。
