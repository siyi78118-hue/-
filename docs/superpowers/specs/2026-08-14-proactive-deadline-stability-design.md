# 主动私聊到期时间稳定性设计

## 问题

Android 普通私聊回复落地后，如果模型没有显式给出下一次主动私聊时间，Web 侧不会立即替换此前遗留的“随机抽取”任务。旧任务到点后才发现会话阶段已经变化，于是只改排下一轮而不执行主动私聊。用户因此会看到“最近私聊”时间向后跳，却没有收到消息。

## 产品规则

1. “最近私聊”表示下一次主动私聊尝试的固定到期时间，不是最近一次聊天时间。
2. 用户或虞栖产生新的普通私聊消息后，系统可以根据最新对话重新计算下一次到期时间；这是有依据的改期。
3. 最后一条新消息处理完成后，如果没有新的对话、任务执行结果、明确失败或用户设置变更，已有到期时间必须保持不变。
4. 前台检查、打开设置、应用重启、云端状态核验和普通重同步只能校验或恢复同一任务，不得生成新的 jobId 或推迟 dueAt。
5. 到期时必须真正进入主动私聊执行链。只有执行结果为可见消息、权威跳过或明确失败后，才可安排下一轮。

## 实现边界

- Android 普通私聊结果落地后统一调用一个 Web 调度入口：
  - 有模型提供的合法时间时使用该时间；
  - 没有时使用现有 `proactiveIdleMinutes` 计算计划时间；
  - 立即替换与当前会话阶段不符的旧随机任务。
- 已有未来任务且会话没有新消息时，前台/启动检查保留原 `jobId` 和 `dueAt`。
- 云端缺失同一任务时，只用相同 `jobId`、`dueAt` 重传；不得重新抽签。
- 朋友圈、角色安排和手动测试任务不在本次修改范围内。

## 验收

1. 给定一个未来的随机私聊任务，普通 Android 私聊回复落地且没有显式计划时，任务立即替换为计划任务。
2. 普通私聊回复携带显式计划时，使用显式时间。
3. 在没有新消息的情况下连续执行前台检查、重启恢复和云端核验，`jobId`、`dueAt` 保持完全一致。
4. 到期任务不会仅因会话阶段不匹配而白等一轮；阶段应在新消息落地时提前收敛。
5. 新消息确实发生后允许重新生成 `jobId` 和 `dueAt`。
6. 现有主动私聊、D1 云闹钟、FCM、离线恢复和旧 Web 直聊回归全部通过。
